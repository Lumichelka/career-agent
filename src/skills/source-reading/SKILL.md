# 何时使用

用户要求核对某个高校就业网/公众号为什么抓不到、页面结构是否变化、或需要从截图/文章中读出招聘信息时使用。

# 核心原则

- 先确认**网站本身**是否可访问、是否登录、是否改版，再判断解析器。
- 优先用浏览器真实页面（BrowserSkill/Agent Window）和截图；不要只用 HTTP 状态猜。
- 不能从截图确认的数字、单位、日期，不写进结论。
- 需要人工登录/验证时，明确请用户操作并等待；用户可取消该环节。
- 一个来源失败，不代表这所学校没有信息；继续找主站、就业公众号、省级平台等替代渠道。

# 证据顺序

1. 真实浏览器页面/截图（首选）
2. DOM 文本与链接
3. 接口 JSON/HTML
4. 用户提供的截图或正文（必须标注“用户提供，待核对”）

# 失败分诊

| 现象 | 判断 | 处理 |
| --- | --- | --- |
| ERR_CONNECTION_TIMED_OUT / DNS | 站点/网络 | 换网络/浏览器；找公众号/省级平台 |
| 403/412/验证码 | 反爬 | 不绕过；请用户登录/截图；改走公众号 |
| 200 但正文空/登录墙 | 登录 | 等用户登录 Agent Window；或改用公众号 |
| 200 但列表 0 条 | 页面改版或选择器失效 | 检查真实 DOM/截图；更新适配器 |
| 有活动无单位 | 详情结构缺失 | 标 `projects unsupported`；不伪造项目 |
| 公众号“环境异常” | 微信验证 | Edge 渲染/粘贴正文/用户截图；不绕过 |

# 每站读取方案

- **四川大学**：列表静态可读；双选会详情常 483，但参会单位走 `getjobfaircorporationlistdata` POST，不需要绕过 WAF。
- **四川农业大学**：列表页面返回 JSON；直接解析 JSON，不依赖前端渲染。
- **西南交通大学**：直接 GET 日历接口会报 404；适配器必须 POST。双选会详情单位表被页面注释，项目标 unsupported。
- **西南石油大学**：双选会列表和参会单位是两个接口；单位分页读取，不能只看第一页。
- **上海财经大学**：匿名 GET JSON 页会报 404；适配器必须 POST，每页最多 10 条。
- **电子科技大学**：Nuxt 页面背后的 `onSiteCalendar` 是数据源；不要从首页通知里猜活动。
- **西南财经大学**：robots 禁止自动抓取；只用用户提供的页面截图/正文或公众号。
- **中央财经大学**：当前网络超时；不伪造活动；找官方公众号/省级平台。
- **对外经济贸易大学**：首页可能被全屏 banner 覆盖；栏目无结构化活动时，用用户截图或手动活动导入。
- **24365 / 国聘**：登录型平台；需要用户登录 Agent Window，或明确取消该环节。
- **公众号**：文章正文优先；账号主页按钮常弹“前往微信”，不要假装抓到了账号文章列表。

# 人工登录/截图协议

1. 打开目标页面，说明需要用户做什么（登录/扫码/提供截图）。
2. 等待用户完成；不要替用户输入账号密码或验证码。
3. 用户取消时，记录“用户取消”，不再重复要求。
4. 用户发截图时，先确认截图对应网站/页面，再读；无法辨认的字段留空。

# 替代渠道

学校主站就业栏目 → 学校就业公众号（如西财校招）→ 省级高校毕业生就业平台 → 24365/国聘 → 用户提供的截图/推文。

# 输出

- 来源、页面 URL、检查时间
- 可访问性/登录/页面结构
- 能确认的活动/项目及原文证据
- 失败阶段与替代路径
- 明确标注“未确认/无法读取”的字段
