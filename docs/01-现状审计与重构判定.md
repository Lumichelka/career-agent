# 01 · 现状审计与重构判定

> 审计对象：`F:\职向` 当前版本（2026-10-23）。
> 审计方法：逐文件阅读 + 实际运行 + 用真实站点验证 + 自动化测试。
> 结论先行：**这个项目的骨架（账号隔离、工具调用、结构化交付、安全约束）值得保留；但"模型接入层"和"业务能力层"必须重构，否则既连不上模型，也做不了作业要求的事。**

---

## 1. 原项目是什么

一句话：一个**本机运行的单页求职对话应用**。用户在网页里聊天，服务端调用"本机 Codex"或"OpenAI/Anthropic 兼容接口"，模型可以调用少量工具（BOSS 直聘、小红书、SearXNG 搜索），最终返回结构化 JSON（回答、记忆、简历文稿、来源、图表），由前端渲染成对话。

它有明确的价值主张，也有一套认真做过的安全设计：

| 设计 | 位置 | 评价 |
| --- | --- | --- |
| 账号 + scrypt 加盐密码 | `accounts.mjs` | 保留。实现正确，有限流、时序安全比较 |
| 每账号独立数据目录 | `server.mjs` `tenant()` | 保留。聊天、附件、配置、浏览器资料隔离 |
| 平台工具桥接令牌 | `server.mjs` `bridgeTokens` | 保留。模型只能访问当前运行任务的租户 |
| 不让模型代投递/发消息 | `agent.mjs` INSTRUCTIONS | 保留。合规边界写得比较清楚 |
| 结构化交付 + 交付检查 | `workflow.mjs` | 改造。检查项要扩展到"招聘信息真实性" |
| 平台浏览器只在本人登录后读取 | `platforms.mjs` | 保留。检测密码框/验证码，不读凭据 |

## 2. 模块清单与重构判定

| 文件 | 职责 | 规模 | 判定 | 说明 |
| --- | --- | --- | --- | --- |
| `server.mjs` | HTTP 路由、账号、会话、NDJSON 流 | ~20KB | **改造** | 路由逻辑可留，绑定地址/Host 校验/会话列举要改 |
| `agent.mjs` | 提示词、规划→执行→复核 | ~14KB | **改造** | 循环设计好，提示词要加入"线下招聘"能力 |
| `api-model.mjs` | OpenAI/Anthropic 接口调用、工具循环 | ~22KB | **重写** | 无重试、无流式、无代理、错误笼统、JSON 易失败 |
| `model-settings.mjs` | 配置校验与保存 | 6KB | **重写** | Key 只在内存、无预设、局域网 HTTP 被禁 |
| `context.mjs` | 附件分块检索 | 2KB | 保留 | 简单的词袋检索，够用 |
| `platforms.mjs` | Playwright 打开 BOSS/小红书 | 6.5KB | 保留 | 只扩展平台即可 |
| `platform-mcp.mjs` | 把平台工具暴露给 Codex | 2.6KB | 保留 | Codex 模式才用 |
| `tool-policy.mjs` | 工具参数校验、去重 | 2.8KB | 改造 | 新增工具要同步登记 |
| `workflow.mjs` | 计划解析、交付检查 | 1.2KB | 改造 | 加"来源/地点/时间"检查 |
| `index.html` + `ui-model.js` | 单页界面 | 34KB | 改造 | 保留布局，模型面板重做 |
| `plan.schema.json` / `response.schema.json` | 输出结构 | 小 | 保留 | 结构合理 |
| **缺失** | 招聘信息采集、排班、导出、公司调研、体检 | — | **新增** | 本次补齐 |

## 3. 十个具体问题（都有证据）

### P1 默认后端是本机 Codex，而这台机器根本没装 Codex

- `model-settings.mjs` 的 `DEFAULT_MODEL.mode` 原本是 `'codex'`。
- 实测 `C:\Users\<用户>\AppData\Local\OpenAI\Codex\bin` 不存在。
- 于是新用户第一次发言就会得到 `未找到 Codex 安装，请先打开并登录 Codex。`

**这是"API 连接问题"的第一个高概率来源**：用户以为自己在用 API，实际后端还是 Codex。

### P2 API Key 只存在内存，重启就"消失"

- 原 `ModelSettings` 把 `this.key` 放在进程内存，页面提示也写着"仅本次运行保存"。
- 用户重启后再对话 → 401 → 以为是"接口坏了"。

### P3 会话列表会把配置文件当成聊天记录，直接崩溃

原 `server.mjs` 的 `/api/sessions` 遍历目录下所有 `.json`，包括 `model-settings.json`。该文件没有 `updatedAt`，排序时抛：

```
Cannot read properties of undefined (reading 'localeCompare')
```

**已在本机复现**：登录成功后界面卡在报错。这是隐藏很深的一个必现 bug。

### P4 用"机器人 UA"抓高校站点会被直接 403

实测（同一 URL，只改 UA）：

| 站点 | 自定义 UA | 浏览器 UA |
| --- | --- | --- |
| 上海财经大学 宣讲会接口 | `code=403 需要登录查看` | `200 + 19 条数据` |
| 中山大学 就业网首页 | `403 Forbidden (nginx)` | `200` |

### P5 高校站点还有"匿名限额"

上海财经大学宣讲会 JSON 接口：

| 每页条数 | 结果 |
| --- | --- |
| 10 | `200` |
| 20 / 30 / 40 | `code=403 您选择的宣讲会信息需要登录查看` |

即：**必须翻页，不能一次要一页 40 条**。

### P6 没有代理、没有重试、没有流式

- 原 `runApiModel` 单次 `fetch`，超时 180 秒，失败即抛。
- 不支持 `HTTPS_PROXY`（Node 原生 fetch 默认不读系统代理）。
- 不支持 SSE 流式，长输出容易被超时截断。

### P7 输出上限写死 4096，长 JSON 会被截断

原 `messages` 协议固定 `max_tokens: 4096`。一份简历 + 分析 + 来源的 JSON 很容易超过，截断后表现为"模型未返回有效的结构化结果"——用户又会以为是接口问题。

### P8 模型返回的 JSON 稍不规范就失败

原 `parseResult` 直接 `JSON.parse(raw)`。模型加一句"好的，以下是结果："或尾逗号就报错。没有修复逻辑。

### P9 无法多设备访问（三重锁）

1. `server.mjs` 只 `listen(port,'127.0.0.1')`；
2. 请求 `Host` 必须等于 `127.0.0.1:4189`，否则 403；
3. `validateEndpoint` 只允许 HTTPS 或 `localhost`，局域网 HTTP 接口直接被拒。

所以手机、平板、另一台电脑都进不来；自建网关放在 NAS 上也填不进去。

### P10 业务能力和新要求完全不匹配

原项目只有"聊天 + BOSS/小红书 + 简历文稿"，而新课要求是：

- 采集多所高校的**线下**招聘信息（官网 / 公众号 / 双选会）
- 整理成**时间安排表**，做行程规划
- 公司调研
- 定向改简历 + 面试准备

上述四块在原项目里**一块都没有**：没有信息源注册、没有采集、没有存储、没有排班、没有导出、没有地图。

## 4. 与新需求的差距矩阵

| 作业要求 | 原项目 | 差距 | 优先级 |
| --- | --- | --- | --- |
| 1.1 四川双一流 / 财经强校 / 双选会 / 其他单位 | 无 | 需建"信息源注册表" | P0 |
| 1.2 公众号 / 就业网 / 其他途径 | 无（只有 BOSS、小红书） | 需多通道适配器 | P0 |
| 1.3.1 抓取失败要反馈并给替代方案 | 无 | 需失败分级 + 降级链 | P0 |
| 1.3.2 确认结果真实有效 | 只有"来源链接" | 需链接复核、置信度、复核按钮 | P0 |
| 1.4 培训 / 双选会 / 宣讲会 / 其他 | 无 | 需活动类型模型 | P0 |
| 2.1 字段识别（公司/时间/地点/网申…） | 无 | 需结构化抽取 + 详情页补全 | P0 |
| 2.2 公司调研 | 无（有搜索工具但需自配） | 新增调研工具 | P1 |
| 2.3 排班 + 地图行程 | 无 | 新增冲突检测、通勤估算、ICS 导出 | P0 |
| 3.1 定向简历 + 面试问答 | 有简历文稿（纯文本） | 可用，但缺 JD 对照与版本管理 | P1 |
| 多设备使用 | 仅本机 | 需局域网/私有组网/云部署方案 | P0 |
| 模型接入稳定 | Codex 默认、Key 内存、无代理 | 需预设 + 持久化 + 体检 + 备用链路 | P0 |

## 5. 重构判定总结

### 保留（约 55%）

- 账号体系、租户隔离、桥接令牌
- 规划 → 执行 → 复核的三段式智能体循环
- 结构化输出 + 交付检查的思路
- 平台浏览器"本人登录、只读、不代操作"的边界
- 附件解析（docx/pdf）与前端渲染

### 改造（约 25%）

- `server.mjs`：绑定地址、Host 校验、会话过滤、新增路由
- `agent.mjs`：提示词加入"线下招聘/公司调研/排班"
- `workflow.mjs`：交付检查加入地点/时间/来源
- `tool-policy.mjs`：登记新工具与参数校验
- `index.html` / `ui-model.js`：模型面板重做

### 重写（约 10%）

- `api-model.mjs`：重试、流式、代理、JSON 修复、错误分层、备用链路
- `model-settings.mjs`：供应商预设、Key 加密持久化、局域网 HTTP 开关

### 新增（约 30% 工作量）

```
providers.mjs      供应商目录与地址规范化
proxy-fetch.mjs    HTTP CONNECT 代理（零依赖）
keyvault.mjs       AES-256-GCM 本地密钥库
diag.mjs           七阶段接口体检
diag-cli.mjs       命令行体检
recruit/sources.mjs  信息源注册表（13 个源）
recruit/fetch.mjs    抓取（UA/编码/限速/robots/重试）
recruit/collect.mjs  采集编排 + 结构化
recruit/store.mjs    SQLite 存储（活动/原始页/运行记录）
recruit/schedule.mjs 排班、冲突、通勤、ICS/CSV/Markdown
recruit/api.mjs      Web API
recruit/cli.mjs      命令行采集/导出/复核
recruit/page.html    招聘日历页面
ui-model.js          模型设置增强面板
```

## 7. 一句话结论

> 原项目不是"不能用"，而是**默认配置把它自己锁死在本机 Codex 上**，同时缺少作业真正需要的采集与排班能力。
> 本次重构把"模型接入"变成可诊断、可持久、可多端的工程问题，把"招聘信息"从聊天话题变成有数据源、有证据、有日历的真实系统。
