# 03 · 接口连接与多设备部署

> 你遇到的"API 连接问题"，90% 不是代码写错，而是**配置、网络或协议不匹配**。
> 本文先给根因清单，再给 5 种可替代的接口方案和 5 种多设备方案，最后是可直接照做的部署步骤。

---

## 1. 先定位：API 为什么连不上

### 1.1 根因清单（按发生概率排序）

| # | 根因 | 典型表现 | 原项目是否有此坑 | 现在怎么解决 |
| --- | --- | --- | --- | --- |
| 1 | **后端还是"本机 Codex"** | `未找到 Codex 安装，请先打开并登录 Codex` | 有（默认 `mode:'codex'`，本机未装） | 默认改为 API；Codex 降为可选项 |
| 2 | **Key 没保存/重启丢失** | 昨天能用，今天 401 | 有（Key 只在内存） | AES-256-GCM 加密落盘，重启仍在 |
| 3 | **协议选错** | 404 / "未返回 Chat Completions 消息" | 有 | 预设自动带协议；404 直接提示"协议或模型名" |
| 4 | **模型名写错** | 404 model not found | 有 | 预设填默认模型；体检单独报"路由" |
| 5 | **地址形态不对** | 404、双重路径 `/v1/chat/completions/chat/completions` | 有 | 自动去重、自动补 `/v1` 路径 |
| 6 | **需要代理但没配** | `fetch failed` / `ETIMEDOUT` | 有（不支持代理） | 支持 `http://` 代理，零依赖 CONNECT 隧道 |
| 7 | **局域网/自建网关是 HTTP** | 保存即报"必须 HTTPS" | 有（只允许 localhost） | 勾选"允许局域网 HTTP"即可 |
| 8 | **输出被截断** | `模型未返回有效的结构化结果` | 有（硬编码 4096） | 上限可调（默认 8192），支持流式 |
| 9 | **模型不返回纯 JSON** | 同上 | 有 | 自动去围栏/修尾逗号/去前后废话 |
| 10 | **额度/频率限制** | 429 | 无重试 | 指数退避重试；可配备用接口自动切换 |
| 11 | **额度耗尽** | 402 / balance | 提示笼统 | 明确提示"额度不足" |
| 12 | **证书问题**（自建） | `SELF_SIGNED_CERT_IN_CHAIN` | 提示笼统 | 体检单列 TLS 阶段，建议换证书或本机 HTTP |

### 1.2 一分钟排查树

```
保存配置后点「一键体检」
│
├─ 地址格式 ✘ ─────────── 按预设重选，或填到 /v1 为止
├─ 域名解析 ✘ ─────────── 拼写？DNS？需要代理？→ 换国内供应商
├─ 端口连通 ✘ ─────────── 服务没起 / 端口错 / 防火墙
├─ HTTPS 证书 ✘ ──────── 自建请换受信任证书；本机用 127.0.0.1
├─ 接口与鉴权 ✘
│   ├─ 401/403 ───────── Key 错、过期、无权限
│   ├─ 404 ────────────── 协议错（chat/responses/messages）或模型名错
│   ├─ 429 ────────────── 额度/频率 → 稍后或备用接口
│   └─ 5xx ────────────── 服务端问题 → 换时间/换供应商
├─ 工具调用 ! ─────────── 模型不支持 function calling → 换 DeepSeek/GLM/Qwen
└─ JSON ! ─────────────── 模型结构化能力弱 → 换更强模型
```

### 1.3 体检真跑一次长这样

（本机实测：只填了 DeepSeek 地址和模型，没有 Key）

```
✔ 运行环境   Node v24.18.0 · win32 · 代理：未配置
✔ 接口地址   https://api.deepseek.com/chat/completions
✔ 域名解析   182.140.248.155, 139.200.130.136 · 10ms
✔ 端口连通   api.deepseek.com:443 · 5ms
✔ HTTPS 证书 TLSv1.3 · 颁发者 TrustAsia Technologies, Inc.
✘ 接口与鉴权 HTTP 401 · Authentication Fails (governor)
   └ 建议：鉴权失败：Key 不对、过期或无权限。

结论：鉴权失败：Key 不对、过期或无权限。
```

结论：**网络和地址都没问题，只差一个 Key**。这正是原来那句笼统的"连接失败"说不清楚的地方。

## 2. 五种接口方案（按预算与场景选）

| 方案 | 做法 | 成本 | 速度 | 稳定性 | 适合谁 |
| --- | --- | --- | --- | --- | --- |
| **A. 国产直连 API** | DeepSeek / 智谱 GLM / 通义 / Kimi / 硅基流动 | 几元~几十元 | 快 | 高 | **首选**，国内免代理 |
| B. 统一网关 | One API / New API / LiteLLM 自建，一个 Key 多模型 | 服务器成本 | 中 | 高 | 小组共用、想随时换模型 |
| C. 本地模型 | Ollama / LM Studio（qwen2.5:7b 等） | 0（需 8GB+ 内存） | 慢 | 中 | 断网演示、无预算 |
| D. 中转/反向代理 | Cloudflare Worker 自建代理或第三方中转 | 低-中 | 中 | 中 | 必须用境外模型时 |
| E. 每用户自带 Key（BYOK） | 每个账号填自己的 Key | 0 | 取决于各自 | 高 | 课程共同测试 |

### 推荐组合

```
主接口：DeepSeek（chat，便宜、支持工具调用）
备用接口：智谱 glm-4-flash（有免费额度）或本地 Ollama
搜索：自建 SearXNG（可选，公司调研/公开检索才需要）
```

本项目已内置 14 个预设：DeepSeek、智谱、Kimi、通义、硅基流动、火山方舟、OpenAI、Anthropic、OpenRouter、Gemini、Ollama、LM Studio、自建网关、自定义。

### 智谱免费档示例（零成本演示）

1. 打开 <https://bigmodel.cn/console> 注册，创建 API Key。
2. 页面 →「模型与接口设置」→ 供应商预设选 **智谱 GLM（有免费档）**。
3. 模型名 `glm-4-flash` 已自动填好，粘贴 Key。
4. 点「一键体检」，全绿后保存。

### 本地模型示例（完全离线）

1. 安装 Ollama，执行 `ollama pull qwen2.5:7b`。
2. 预设选 **本机 Ollama**，地址 `http://127.0.0.1:11434/v1`，模型 `qwen2.5:7b`。
3. 体检。
4. 注意：7B 级模型的工具调用和 JSON 稳定性一般，适合"能跑通"的兜底，不建议做复杂简历改写。

## 3. 多设备：五种方案对比

| 方案 | 访问范围 | 成本 | 安全 | 部署难度 | 浏览器工具 | 适合 |
| --- | --- | --- | --- | --- | --- | --- |
| **A. 局域网直连** | 同一 Wi-Fi | 0 | 中（HTTP 明文） | ★ | ✅ 在本机 | 宿舍/家里，手机看日历 |
| **B. Tailscale 私有组网** | 任何网络 | 0 | **高**（加密隧道） | ★★ | ✅ 在本机 | **推荐**：回家/实习都能用 |
| C. 云服务器 + 域名 + HTTPS | 公网 | ￥50–100/月 | 高（配好 TLS） | ★★★★ | ⚠️ 需无头浏览器，扫码登录麻烦 | 小组多人长期用 |
| D. PaaS（Render/Railway 等） | 公网 | 免费档有限 | 高 | ★★★ | ❌ 无持久磁盘，Chromium 跑不动 | 只做 API + 日历 |
| E. 本地优先 + 同步 | 各设备各跑 | 0 | 高 | ★★ | ✅ | 不信任云、数据敏感 |

### 本项目已实现 A，并给出 B 的操作步骤

**A. 局域网（已实现并实测）**

双击 `开始使用-局域网.cmd`，控制台会打印：

```
职向已启动：http://127.0.0.1:4189
局域网访问地址（同一 Wi-Fi 的手机/平板/另一台电脑）：
  http://10.61.108.25:4189
```

手机浏览器打开这个地址 → 用账号登录 → 点「招聘日历」。
实测：局域网 IP 返回 200；伪造 `Host: evil.example.com` 返回 403。

**B. Tailscale（推荐给"不在同一 Wi-Fi"）**

1. 电脑和手机都安装 Tailscale，登录同一账号。
2. 电脑上仍用 `开始使用.cmd`（只监听 127.0.0.1 也行）。
3. 在 Tailscale 管理台开启 **MagicDNS** 与 **HTTPS Certificates**。
4. 电脑上执行（把 `<机器名>` 换成你的）：
   ```
   tailscale serve --bg 4189
   ```
5. 手机会得到一个 `https://<机器名>.<tailnet>.ts.net` 地址，直接访问。
6. 若页面提示 Host 被拒，在启动前设置环境变量：
   ```
   set CAREER_ALLOWED_HOSTS=<机器名>.<tailnet>.ts.net
   ```

> Tailscale 的流量是端到端加密的，不需要把端口暴露到公网，也不需要买域名。

**C. 云服务器（小组共用）**

```
域名 → Caddy/Nginx（自动 HTTPS）→ 127.0.0.1:4189
```

- 服务器上 `CAREER_HOST=127.0.0.1`，由反向代理转发；
- `CAREER_ALLOWED_HOSTS=你的域名`；
- 账号系统已经隔离数据，但仍建议只给组员开账号；
- **平台浏览器（BOSS/小红书）在无头服务器上扫码登录很别扭**，建议这类任务仍在本机做。

## 4. 安全清单（多设备必看）

- [x] 默认只监听 `127.0.0.1`，不会一装好就暴露
- [x] 所有接口要 `x-career-token` + 登录 Cookie 双校验
- [x] `Host` 白名单，防 DNS rebinding
- [x] `Origin` 校验，防跨站请求
- [x] 密码 scrypt 加盐，Cookie `HttpOnly; SameSite=Strict`
- [x] API Key AES-256-GCM 加密落盘，按账号隔离
- [x] 模型只能通过一次性桥接令牌访问当前任务数据
- [ ] 局域网是 HTTP 明文：**只建议在可信网络使用**
- [ ] 不要把 4189 端口直接映射到公网（没有 WAF、没有限流）
- [ ] 分享给别人时，只发代码，不发 `.data`（里面有简历、账号、Key、登录态）

## 5. 常见问题

**Q：页面能打开，但一直提示"请先登录自己的测试账号"？**
A：第一次使用看 `.data\首次登录.txt`；忘记密码可删掉 `.data\accounts.json` 重新初始化（会清空账号，慎用）。

**Q：换电脑要重新配吗？**
A：把整个文件夹拷过去即可（Node 23+，`npm ci`）。账号、会话、采集数据、加密 Key 都在 `.data` 里。**但 `.data` 含隐私，别发给别人。**

**Q：能同时开两个服务吗？**
A：可以，改 `PORT` 环境变量（如 `set PORT=4190`），但同一个 `.data` 不建议两个进程同时写。

**Q：模型回复很慢/超时？**
A：换 `deepseek-chat` 而不是 `deepseek-reasoner`；把单次输出上限调到 4096；把任务拆小。

**Q：公司调研/联网搜索用不了？**
A：需要单独配置 SearXNG 搜索地址。模型接口 ≠ 搜索引擎。没有搜索服务时，工具会明确返回"不可用"，不会编造。

## 7. 如果要换一种方式实现这个智能体

不一定非要"自己写前后端"。下面几种替代路线，按"多端体验 / 采集能力 / 可控性"比较：

| 路线 | 做法 | 多端 | 采集能力 | 成本 | 适合 |
| --- | --- | --- | --- | --- | --- |
| **A. 保留本项目 + 私有组网** | 现在这套 | 中（浏览器） | **强**（可开本机浏览器、可抓高校站） | 0 | **当前最优** |
| B. 扣子 / Coze 低代码 | 把提示词和插件搬上去，发到微信/飞书 | **强** | 弱（只能用平台插件/API） | 低 | 只想演示对话 |
| C. Dify / FastGPT 自部署 | 工作流 + 知识库 + API | 中（需自己做前端） | 中（HTTP 节点） | 服务器成本 | 团队协作、可视化编排 |
| D. Remote MCP Server | 把采集/排班做成 MCP 工具，用任意支持 MCP 的客户端连 | **强**（客户端自带多端） | 强（服务端跑采集） | 低-中 | 想在手机 App 里直接用 |
| E. 微信小程序 / 公众号 H5 | 后端复用本项目的 API | **最强**（微信内） | 中 | 需备案/域名 | 面向同学推广 |
| F. 纯人工 + 通用大模型 | 不做系统，用提示词模板 | 强 | 无 | 0 | 一天交作业 |

**建议**：

- 课程作业：**A**，成本最低、采集最真。
- 想给同学用：**A + E**（保留采集后端，前端做小程序/H5）。
- 想"在任何客户端里用"：**D**——本项目已经有 `platform-mcp.mjs` 的 MCP 经验，把 `recruit` 的几个函数注册成 MCP 工具即可，手机上的 MCP 客户端直接调用。

> 注意：B/C 类平台通常**跑不了需要登录的浏览器**，也拿不到高校站点的隐藏 JSON 接口。采集这件事，绕不开"自己写适配器"。

---

## 8. 一句话总结

> **接口问题**：先体检，再按阶段修；首选国产直连，配一个备用接口。
> **多设备问题**：同 Wi-Fi 用局域网；跨网络用 Tailscale；小组共用再上云。
> 不要把"模型能连上"和"能搜到真实信息"混为一谈——后者还需要采集通道与搜索服务。
