## 3. 五分钟演示脚本

**0:00–0:40 开场**
> "很多同学找实习，信息散在几十个学院的公众号和就业网里。我们做了个智能体，把这些线下招聘抓回来，排成一张能进手机日历的表。"

**0:40–1:30 采集**
- 打开招聘日历 → 点「采集全部已接入源」。
- 指运行记录："四川大学、上财、南开、中山成功；中央财经超时——我们会明确告诉你失败原因，而不是假装没有活动。"

**1:30–2:30 行程表**
- 展示 10-23 那天的卡片："这两场在成都，这几场在上海，系统标了『同日异地，需取舍』而不是误报冲突。"
- 点「复核来源」→ "它真的回去打开了那个页面。"

**2:30–3:10 导出**
- 导出 `.ics` → 用手机日历打开 → "到点提醒，点地址直接导航。"

**3:10–4:00 智能体**
- 问："未来两周成都的宣讲会帮我按天排一下，标出冲突。"
- 展示计划 → 工具调用 → 回答。

**4:00–4:40 简历**
- 上传简历，贴一段 JD："按这个岗位改，不要编造经历。"
- 展示"来源/事实"约束与可下载文稿。

**4:40–5:00 收尾**
- "如果模型连不上，点一键体检，它会告诉你卡在 DNS、证书还是 Key。手机也能用。"

## 4. 技术亮点（挑 3 个讲深）

### 亮点 1：把"连接失败"拆成 7 个可诊断阶段

不是一句 `fetch failed`，而是 DNS → TCP → TLS → 鉴权 → 工具 → JSON 逐段报告，并给修复建议。这是工程能力，不是调 API。

### 亮点 2：真实站点的三种适配器

- 静态 HTML（川大）
- 隐藏 JSON 接口（上财，翻页 10 条/页）
- 浏览器渲染（兜底）

并且踩过并解决了真实的反爬：**自定义 UA 被 403、匿名请求每页超 10 条被拒**。这些细节能讲出"真的做过"。

### 亮点 3：数据可信度设计

`confidence`（字段完整度）+ `verified`（人工/自动复核）+ `raw_text`（原文留存）+ `runs`（采集审计）。
明确区分"没抓到"和"没有活动"。

### 亮点 4：多端与安全

Host 白名单、Origin 校验、Token + Cookie 双校验、Key 加密落盘、租户隔离。
局域网实测 200，伪造 Host 实测 403。

### 亮点 5：可验证

31 个自动化测试，覆盖地址规范化、Key 加密、流式聚合、429 重试、排班冲突、ICS 生成、采集解析。

## 5. 老师可能问的问题

**Q：你们的数据是编的吗？**
A：不是。每条都有 `source_url` 和 `fetched_at`，页面上能点开；入库时保存了原始页面文本；点"复核来源"会重新抓取比对。抓不到的源会显示失败原因。

**Q：微信公众号怎么解决？**
A：自动爬公众号违反平台条款且极易失效，我们选择"用户转发链接 → 智能体解析"的半自动路线，并说明了 RSSHub/wechat2rss/公众平台接口三种技术路径与风险。这是取舍，不是遗漏。

**Q：为什么不用现成的招聘 App API？**
A：多数不开放、有授权限制；高校就业网才是"线下宣讲/双选会"的第一现场。我们优先官方公开页面。

**Q：大模型在这里到底做了什么？**
A：三件事：①规划与工具选择；②自由文本字段抽取（岗位要求、投递方式）；③简历改写与面试问答。规则能做的（时间/地点/单位）不交给模型，保证稳定。

**Q：如果模型胡说怎么办？**
A：提示词禁止编造；输出带来源；`checkDelivery` 检查"声称检索但没有工具调用"；简历数字必须来自用户素材。

**Q：多设备安全吗？**
A：默认只监听本机；开局域网要账号登录；跨网推荐 Tailscale 加密隧道；不建议直接暴露公网。
