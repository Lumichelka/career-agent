> 日期：2026-10-26 ｜ 状态：计划（待拆票执行） ｜ 依据：当前 owner 库只读核对
> 关联：docs/plan/10-采集与生命周期.md、docs/plan/19-平台与公众号.md、docs/plan/20-日历与招聘项目.md、README「信息源」表

## 0. 结论摘要

1. 数据来源不是「全坏了」，而是三类问题并存：访问/合规受限（央财、西财、对外经贸、24365、国聘）、校验方式不适配（SWJTU/SUFE/SICAU/UESTC 的详情页是 JS/SPA 或共用一个列表 URL）、详情与项目缺失。
2. 当前最大可用性缺口不是「再多几个学校」，而是「已有 157 场活动里只有 6 场挂了项目，513 个项目 0 个岗位/要求」——用户无法按岗位方向筛岗。
3. 覆盖面上，金融/银行方向只剩上财稳定可用；公众号 10 个账号里 9 个没有文章；公司库只有 1 家。补全这三块是 P1 的重点。

## 1. 核对口径

- 对象：owner 账号（5cc08541-8fdd-46e1-9d34-ef6cbdb46025）的 recruit.db / wechat.db / company.db。

- 说明：verify 会按设计把 verified 与 notes 写回复核标记，不修改活动/项目的业务字段；其余核对只读。
- 时间：数据截至 2026-10-26；最近一次采集 2026-10-25 上午，已约一天未刷新。

## 3. 数据质量快照

- 活动 157 场，今日 30 场，日期覆盖 2026-05-15 至 2026-12-25。
- 项目 513 个，仅挂 6 场活动（3.8%）；513 个项目里 0 个岗位、0 个要求、500 个投递链接。
- 活动级 positions / requirements / apply_url 全部为空。
- 抽样校验 100 条：49 通过、51 待确认；其中 SWJTU/SUFE/SICAU/UESTC/SWPU-jobfair 的失败多为 SPA 假阴性，不可当失效删除。
- 公众号：10 个账号、4 篇文章；9 个账号为 0；2 篇挂「未归类公众号」；1 篇 example.com 演示数据。
- 公司库：company.db 仅 1 家公司；搜索服务未配置。
- sources.last_status 多为 ok 但 last_count=0；该字段只统计新增，无法反映本次抓取/更新量，易误判为源无数据。

## 4. 关键判断

1. 数据可信问题优先：先让「来源状态、校验结论、数据年龄」可信，再谈扩覆盖。
2. 51 条待确认不能批量标失效：需要按源适配校验（JSON/详情接口/浏览器），区分「页面变化」与「JS 壳」。
3. 最大缺口是项目详情：岗位/要求/投递信息全空，导致 157 场活动里只有 6 场可用来筛岗。

## 5. 功能路线图

### P0 · 数据可信

| 功能 | 问题 | 验收 |
| --- | --- | --- |
| 来源健康与新鲜度面板 | last_count 只算新增，看不出抓取量/更新量/数据年龄 | 13 源都有可解释的最近尝试/成功/抓取数；今日数据带新鲜度标识 |
| 来源校验 v2 | 校验用 HTML 标题匹配，SPA/单 URL 源大量假阴性 | 按源适配（JSON/详情/浏览器）；抽样人工复核 20 条误判 <10% |
| 来源生命周期与谱系 | 南开/中山孤儿源残留；注册表与 sources 表漂移 | 0 孤儿源；每条活动可追到当前或历史来源 |
| 双选会项目详情补全 | 513 项目 0 岗位/0 要求 | SWPU/SCU 先行；岗位/要求缺失率降到可解释范围 |

### P1 · 覆盖扩展

| 功能 | 问题 | 验收 |
| --- | --- | --- |
| 通用来源校对 + 财经院校覆盖 | 央财超时、对外经贸无结构化、西财 robots；24365/国聘需登录 | 4 所财经院校至少各有一条可用通道 |
| 公众号采集管线 | 10 账号 4 文章，9 账号为 0，含演示数据 | 9 个空账号能抓到最近文章；文章→活动/项目带来源 |
| 平台岗位入库 | 7 个登录平台只读，岗位未入库 | 平台岗位写入项目表，带来源/时间/置信度，可筛岗 |
| 公司调研数据源 | company.db 仅 1 家；搜索未配置 | 20+ 高频单位有来源可核对的信息，不编造 |

### P2 · 决策与自动化（本轮不建票）

- 可行动视图 + 完整度评分：一键筛「今天/本周可行动」场次。
- 定时刷新与告警：每日采集/校验，失败源与过期数据首页提示。

## 6. 实施阶段

- Phase 1（1–2 周）：P0 全部。验收：13 源状态可解释、0 孤儿源、校验误判 <10%、项目详情缺口可度量。
- Phase 2（2–3 周）：P1 通用来源校对 + 财经院校覆盖。验收：4 所财经院校各有可用通道。
- Phase 3（2–3 周）：P1 公众号 + 平台岗位 + 公司调研。验收：公众号有文章、平台岗位入库、20+ 公司有来源。
- Phase 4（1 周）：P2。验收：每日刷新、可行动视图上线。

## 7. 优先顺序与决策点

- 默认：先 P0（数据可信 + 项目详情），再 P1（覆盖扩展）。
- 若优先金融/银行覆盖，把「财经院校覆盖」提到与 P0 并行；只改先后，不改内容与验收。
