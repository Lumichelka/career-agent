## 0. 范围与不变量

**覆盖**：登录用户在网页端使用模型 API 与外部 Agent 时，模型 Key、外部 Agent 进程与连接、任务上下文与数据目录、平台浏览器登录态、并发与配额的隔离口径；以及这些资源里哪些**不**隔离。

**不覆盖**：出站 MCP 的协商/信封/取消（#13）；入站端点与凭据签发（#21）；模型路由与回退（#17）；审计表与撤销（#15）；聚合/转发的工具面（#22）。

**不变量**（实现必须逐条满足）：

1. 隔离是**应用层访问控制**：单 Node 进程、单 OS 身份。不承诺抵御本机管理员、同 OS 账户的其他进程，或直接读盘；这是部署前提，不是实现缺陷。
2. 每个用户只有一个数据根 `users/<id>`。服务端任何路径都由**已认证用户**推出；请求体里的 `user_id`、路径、`taskId` 一律不能用来换身份。
3. 凭据、会话、模型配置、Agent 配置、平台 Profile、任务证据、审计都不跨用户共享；不设实例级共享 Agent 配置。
4. 模型 Key 只以 `KeyVault`（AES-256-GCM）落盘；`vault.key` 与 `secrets.enc.json` 是一个**不可拆的凭据单元**；不继承服务器环境变量里的 Key。
5. stdio MCP **永久仅 owner**；非 owner 只能配 HTTP。
6. 平台登录态只存在于该用户的 `platform-profiles/<platform>`；不导出、不共享、不代传。
7. 所有上游调用（模型 API、MCP 出站、入站转发）共用一把「在途」闸：每用户 **2** / 全局 **8**；任务层每用户 **2** / 全局 **8**。
8. 配额只管并发，不管花销：不设费用配额（#17）。
9. 日志、trace、错误消息、证据、UI 全链路脱敏，不出现 token、Key、完整上游 URL。
10. 本文只改多用户口径；协议细节与 #13 冲突时以 #13 为准。

## 1. 隔离承诺

### 1.1 层级（决议 A）

隔离靠应用层：一个 Node 进程、一个 OS 身份、一套数据目录。服务端按已认证用户推出数据根，其余全靠权限判断。

**不做真 OS 隔离**：每用户独立 OS 账户或每用户子进程，要求本机为每个登录用户建 Windows 账户，并重做启动、回收、凭据传递，与「一个服务、若干登录用户」的部署模型冲突；它换来的只是「同机管理员」这一本契约已明确接受的风险。

**部署前提**（写进部署文档，验收时逐条对照）：

- 一台机器、一个 OS 账户运行服务；通过局域网或 Tailscale 暴露。
- 数据目录不分享、不进 Git；备份与搬家整目录复制。
- 拥有本机管理员权限的人能读到所有账号的 Key 与平台登录态；这是已知并接受的边界。

### 1.2 每用户资源

| 资源 | 落点 | 隔离手段 |
| --- | --- | --- |
| 对话、附件、记忆、文稿 | `users/<id>/.data/*.json`、`memory/` | 数据根 |
| 业务库 | `users/<id>/.data/{recruit,resume,company,wechat}.db` | 数据根 |
| 模型配置 | `users/<id>/.data/model-settings.json` | 数据根 |
| 模型 Key（含备用链路） | `users/<id>/.data/secrets.enc.json` + `vault.key` | 每用户独立 `KeyVault`，AES-256-GCM |
| 外部 Agent 配置 | `users/<id>/.data/agents.json`（#13） | 数据根 |
| 外部 Agent 连接与缓存 | 进程内连接池，键 `(user, agent)` | #13 |
| 平台浏览器 Profile | `users/<id>/.data/platform-profiles/<platform>` | 每用户独立持久化上下文 |
| 任务证据 | `users/<id>/tasks/<taskId>/evidence/` | #13 §8.2 |
| 审计与幂等表 | `users/<id>/.data`（#15） | 仅本人可见 |

### 1.3 实例级资源（不隔离，必须明说）

| 资源 | 说明 |
| --- | --- |
| 监听端口与 Host | 一个进程、一个端口（默认 4189），跟随 `CAREER_HOST` |
| 实例访问口令 | `local-session-token`，注入每个页面；**不是身份**，只是所有页面共享的护栏 token |
| 入站 `/mcp` 端点与实例开关 | 实例级开关默认关；身份来自每 `(user, client)` bearer（#21） |
| 账号表 | `accounts.json`（scrypt 加盐哈希），实例级 |
| 初始密码文件 | `首次登录.txt`，实例级，保留不清理（见 §7） |
| 模型预设与计价表 | 非密、只读 |
| 浏览器二进制、Node 运行时、`logs/` | 实例级 |

**口径**：身份永远来自 cookie（网页）或 `(user, client)` bearer（入站）；实例访问口令只挡「没拿到页面的请求」，不能当授权用。实现里任何「拿到口令就当成某个用户」的路径都是 bug。

## 2. 模型 Key（决议 A）

- 存储：每用户一本 `KeyVault`；`vault.key` 明文 hex、`0600`；`secrets.enc.json` 每条一个 AES-256-GCM 密文（AAD `career-agent-vault-v1`）。单条损坏只跳过该条。
- 不继承环境变量：`allowEnvironmentKey = false` 对所有账号（现有 `app.mjs`）。
- **凭据单元不可拆**：`vault.key` 与 `secrets.enc.json` 必须一起备份、一起搬家、一起删除。单独复制 `secrets.enc.json` 等于无意义密文；单独复制 `vault.key` 等于泄露全部 Key。
- **不轮换、不找回、不设主密钥口令**。`vault.key` 丢失或损坏 → 该用户的模型 Key 需要重填；业务数据（库、简历、对话）不受影响。
- 迁移：首次启动把旧 `.data` 复制给生成的 owner 账号（现有逻辑），搬完旧目录保留。

## 3. 外部 Agent 进程与连接（决议 A）

- 连接粒度 `(user, agent)`：懒连接、常驻、空闲 30 分钟回收、崩溃退避重连、Windows Job Object / POSIX 进程组回收进程树（#13 §4）。
- **stdio 永久仅 owner**：非 owner 的 UI 不出现该选项，API 返回 `400`（错误码 `STDIO_OWNER_ONLY`）。理由：stdio 等价于以服务器 OS 身份执行命令，`cwd` 锁与环境白名单都拦不住 `node -e "读另一个用户目录"`。
- **不提供「预置命令白名单」**：在单一 OS 身份下，白名单只降低误用、不降低恶意，却会让界面出现一个「看起来安全其实不安全」的选项。
- 非 owner 的可用形态：HTTP MCP server（Dify、自建远程包装、局域网 server）；URL 内嵌凭证整体入 vault，UI 只显示 `scheme://host[:port]/path…`（#13 §3）。
- 将来若引入低权限子账户再开放 stdio，另开票，不在本契约内。

## 4. 任务上下文与数据目录

- 任务只存在于进程内注册表（`running`、`taskEvents`、`bridgeTokens`、`owners`），键是会话 UUID；**跨重启不恢复**（地图 fog 已记录）。
- 任务证据按 `users/<id>/tasks/<taskId>/evidence/` 落盘；模型只看占位（#13 §8.2）。
- `roots/list` 只返回该用户的 `users/<id>` 一个根（#13 §9）。
- 平台桥 token：每任务随机、任务结束即删，只能访问该任务所属租户（现有 `app.mjs` 桥分支）。
- 路径参数只在**该用户自己的数据根**内解析；跨用户的 id 会因为拼出的路径不存在而失败，不需要额外的用户前缀。

## 5. 平台浏览器（决议 B）

- 每用户一个 `PlatformBrowser`，Profile 在 `users/<id>/.data/platform-profiles/<platform>`；同一 Profile 内的操作串行（按 platform 分锁）。
- **不设窗口数量上限**：每开一个平台就常驻一个 Edge 窗口；只在界面提示「多开平台会占用内存，关闭不用的平台可释放」。
- **登出即关闭该用户全部平台窗口**；登录态仍留在 Profile 里，下次打开还在。
- 任务结束**不**自动关窗（用户可能马上要接着看）。
- 不提供导出、迁移、共享 Profile 的入口；平台密码从不进入本应用。

## 6. 并发与配额（决议 A）

| 闸 | 计量单位 | 额度 | 排队 | 超时 |
| --- | --- | --- | --- | --- |
| 上游在途 | 一次模型 API 调用 / 一次 MCP 出站调用 / 一次入站转发调用 | 每用户 **2**，全局 **8** | FIFO | 120s → `QUEUE_TIMEOUT` |
| 任务 | 一个正在执行的对话任务 | 每用户 **2**，全局 **8** | FIFO | 120s → 提示稍后再试 |

细则：

- 「在途」从发出上游请求算起，到收到完整响应（流式到结束）为止；一次流式模型调用在整个流期间占 1 个额度。
- 同一对话已有任务在跑 → `409`（现有行为保留）；同一用户的第 3 个任务排队。
- 入站 `/mcp` 的工具调用计入**该用户**的在途额度——外部 AI 打满的只能是它自己所属用户的额度。
- MRTR 的 `sampling` 是模型调用，计同一把闸；`elicitation` 等人机交互不占额度。
- 一个任务内部同时只有 1 个在途调用，所以「每用户 2 个任务」恰好约等于「每用户 2 个在途」，不会自己把自己饿死；任务内并行取数按 FIFO 在闸内排队。
- 不设费用配额、不做月度账单、不按金额熔断（#17）；本契约只约束并发。

## 7. 账号准入（决议 A）

- **保留自助注册**：拿到页面（含实例访问口令）即可注册，不需要 owner 审批；上限 **100** 个账号。
- 密码 scrypt 加盐；登录 cookie `HttpOnly; SameSite=Strict; 12h`；同一账号 1 分钟内失败 5 次锁定。
- owner = 第一个账号：唯一可用 Codex 与 stdio 的账号；**不是超级查看者**，应用层没有跨用户数据视图。
- `首次登录.txt` 保留在数据目录根部、**不自动清理**；忘记密码的恢复路径仍是「备份后重建账号」（部署文档）。与 §1.1 一致：能读盘的人本来就能读 Key。
- 用户管理面（列表、删除、重置密码）不在本票范围；需要时另开票。

## 8. 明确不做

- 每用户独立 OS 账户或每用户子进程（真 OS 隔离）。
- 用 DPAPI / 凭据管理器包裹 `vault.key`（防拷走）——记录为将来可选项，本契约不要求。
- `vault.key` 轮换、找回、主密钥口令。
- 平台浏览器窗口数量上限、空闲回收。
- 非 owner 的 stdio（含预置命令白名单）。
- 跨用户共享 Agent 配置、连接、缓存、凭据、发现结果。
- 费用配额、月度账单、按金额熔断。
- 用户管理面。

## 9. 验收清单

实现完成后逐条可验：

1. 两个账号的模型 Key 互不可见（`tests/isolation.test.mjs` 已有用例，扩展到备用 Key）。
2. 非 owner 配 stdio → API 返回 `400 STDIO_OWNER_ONLY`；UI 不出现该选项。
3. 两个账号同时打开同一平台 → 两个不同 Profile 路径，登录态互不串。
4. 登出后该用户全部平台窗口关闭，其他用户的窗口不受影响。
5. 上游闸：单用户 3 个并发模型调用 → 第 3 个排队，120s 未获得 → `QUEUE_TIMEOUT`。
6. 任务闸：同一用户第 3 个任务排队；不同用户互不阻塞。
7. 入站 `/mcp` 调用计入该用户在途额度：一个用户打满不影响另一个用户。
8. 桥 token 只能访问当前任务所属租户（现有行为）。
9. 把 `vault.key` 换成另一账号的 → 该用户 Key 解不开、业务数据仍可读。
10. 任意 `/api/*` 都不接受请求体指定用户或路径来换身份。

## 11. 术语

| 术语 | 含义 |
| --- | --- |
| 用户 / 账号 | 网页登录身份，`users/<id>` 的所有者 |
| owner | 第一个账号；唯一可用 Codex 与 stdio 的账号 |
| 在途 | 已发出、尚未结束的一次上游调用 |
| 上游调用 | 模型 API 请求、MCP 出站 `callTool`、入站转发的工具调用 |
| 凭据单元 | `vault.key` + `secrets.enc.json`，不可拆 |
| 平台 Profile | `platform-profiles/<platform>` 下的 Edge 持久化上下文 |
| 应用层隔离 | 靠进程内路径推导与权限判断隔离，不靠 OS 账户 |
