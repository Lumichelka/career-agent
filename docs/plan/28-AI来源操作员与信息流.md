# 28 · AI 来源操作员与信息流

> 日期：2026-10-27 ｜ 状态：implemented（#55–#60 已合并，评审修复见 CHANGELOG v3.3.0） ｜ 依据：ADR 0001/0002/0003、spec #44 数据源核对
> 目标：让 AI 在应用内浏览器里为「代码采不了的难源」做手动兜底，并把结果作为可审计的信息流交给本应用与外部 AI。

## 1. 问题

- 对外经贸、西南财大、24365 的公开页已验证可读/可解析；真正难的是登录后平台与微信公众号（验证/登录/动态渲染）。
- 现有 source-check 只能固定读「列表 + 一场详情」，无法处理登录、banner、文章列表、结构变化。
- 外部 AI 只能读本地库，没有稳定的增量 feed 契约；原始页面与证据不可追溯。

## 2. 决策（已由 ADR 固定）

- AI 操作员是手动兜底，不是主采集路径（ADR 0003）。确定性源优先；失败/阻断/结构变化时用户点「AI 兜底」。
- 复用 source-check 任务，增加 operator 阶段；动作日志 + 每步截图存任务证据；数据写入走写网关 + 审计。
- 应用内 per-user persistent profile；用户可见窗口登录一次，点「已登录」继续；不提取 cookie/密码。
- 允许任意 Playwright 动作与 page.evaluate JS；提示词不是安全边界；单用户本机、可信源、手动、可见、每次确认。
  HTTP 入口不接受客户端 steps/evaluate，步骤只来自服务端 playbook 或进程内注入（公众号账号级 AI 采集）。
- 唯一硬上限：总活跃运行时间 <10 分钟（暂停/人工接管不计时，继续后额度不清零）；不限制列表/详情数量、翻页、步数、模型成本。允许剪贴板；禁止下载/上传；禁止 file/chrome/edge/localhost/私网。
- 触到登录/验证码/异常/时间上限：暂停并转人工接管；用户处理后从停点继续，不判失败；只在实际重启后把遗留等待任务标 failed（OPERATOR_RESTART）。
- 对投递/支付/删除/退出/提交表单做尽力而为的硬确认（合并 playbook.forbiddenActions）；任意 JS 仍可绕过，不宣称是安全边界。
- 信息流 = 规范化记录 + 证据指针 + append-only cursor；career_feed 同时给 /chat 与外部 MCP。
- 原始文本默认脱敏（手机号/邮箱/身份证/微信/联系人），单条 ≤8k；仅 includeRawText:true 返回；不返回 HTML/截图字节。
- 证据 30 天自动清理；feed 条目保留并返回 evidence_available:false；cursor 不倒退。
- 每源一个 Markdown+YAML playbook；首个机制原型为微信公众号（西财校招/上财就业候选）。

## 3. 范围

### In scope

1. source-check operator 阶段：打开可见 profile、登录、AI 动作、动作日志/截图、人工接管、硬确认。
2. 微信公众号 AI 操作员：账号文章列表/正文读取、文章→活动/项目、证据、feed。
3. career_feed 契约：/chat 工具 + 入站 MCP 工具；脱敏 rawText、cursor、evidence_available、upsert/delete/undo。
4. 手动 AI 兜底入口：源卡片「AI 兜底」；失败/阻断时可用；不自动切换。
5. UIBE 确定性解析器：列表 20/页、详情、限速、来源 URL；保留 AI 兜底。
6. SWUFE 保留 source-check 对照；加 AI 兜底入口。
7. playbook 文件与登录/profile 管理。

### Out of scope

- 多用户/远程对外提供 AI 操作员。
- 自动定时 AI 兜底。
- 反检测/stealth/绕过验证码。
- 新建 AI 私有数据库；权威仍是本地审计库。

## 4. 任务与数据

### 任务状态

    queued
    → running_operator
    → waiting_login / waiting_human
    → running_extract
    → waiting_confirmation
    → succeeded / failed / cancelled

- operation_id = taskId:runSeq（runSeq 取该条 write_audit 的 seq；同一任务多次写入可区分）。
- 动作日志 action.jsonl：step, action, target, url, startedAt, durationMs, result, screenshotRef。
- 每步截图；关键步骤额外保留。证据 30 天清理（启动 + 每 6 小时真实删除文件）。
- 数据写入走 write_audit；动作日志不是审计表。
- 每次 AI 采集/兜底必须确认一次；服务重启后 waiting_login / waiting_human 标 failed（OPERATOR_RESTART）。

### Feed

    career_feed({since?, offset?, types?, sourceId?, limit?, includeRawText?})
    → { entries: [{ seq, op, type, id, record, rawText?, changed_at }], nextCursor, nextOffset, hasMore }

- record: id/type/source_id/source_url/fetched_at/confidence/verification/operation_id/evidence_ref/schema_version/updated_at/deleted_at。
- 不传 since 返回当前快照；limit 截断时用 nextOffset 继续（此时 nextCursor=null），取完后才给增量起点；传 since 返回增量。
- 证据根限制在用户数据树内；30 天后 evidence_available:false。
- rawText 先解 HTML 实体再去标签，抹手机号（含空格/连字符）/邮箱/身份证/微信/联系人，8k 上限，仅显式请求。
- 公司记录没有 write_audit 行：只在快照可见，不承诺进增量（已知限制）。

## 5. 源计划

### WeChat（首个机制原型）

- 账号：西财校招（首选）、上财就业（次选）。
- 打开公众号文章列表/正文；微信验证/登录由用户接管。
- 抽取文章→活动/项目；至少 1 单位 + 合法 startAt 才入库；0 编造。
- 成功：至少 3 条记录（不足 3 条标 failed 并给恢复建议）、来源 URL、证据、feed 可查、/chat 可答、总活跃 <10 分钟。
- 只保留账号级「AI 采集」（必须带 accountId）；mp 首页的通用 AI 兜底入口已移除。

### UIBE（确定性源）

- 列表每页 20、共 202 页；详情结构化，详情请求间隔 1.2s。
- 实现 list/detail 解析器、限速、source_url；AI 兜底保留。
- 不猜：列表没有年份/时间就留空并记录原因，不用 09:00 占位，不从页面其他日期推年份。
- **默认 enabled:false，标注「需人工确认 robots」**：页面 JS 仍会 POST robots 禁止的 /front/zp_query/；
  「不直连」不等于合规。解析器/来源校对测试保留。
- 成功（人工确认 robots 后）：一次采集 ≥3 条、字段完整、审计/撤销。

### SWUFE（source-check 对照）

- 保留现有 source-check；加 AI 兜底入口。
- 去重改为归一化标题 + 时间 + 单位（容忍邀请函/全半角/时区措辞差异），不再逐字比较 title+startAt。
- 兜底要求列表与详情是两个不同页面，否则 OPERATOR_SAME_PAGE 失败关闭，不写库。
- 成功：source-check 与 AI 兜底都能产出带证据记录、写同一条记录；对比数据一致。

## 6. 验收

- 三个源各跑一次手动流程；每次总活跃 <10 分钟；0 编造；证据可追溯；可撤销。
  UIBE 的自动采集在 robots 人工确认前不跑；其解析器/来源校对/兜底用 fixture/假页面测试，未做 live 采集。
- /chat 与外部 MCP 都能通过 career_feed 读到增量；rawText 默认不带，显式 true 时脱敏。
- 失败/登录/验证码触发人工接管，恢复后继续；不是重跑；服务重启后遗留等待任务标 failed。
- 30 天证据清理后 feed 仍可消费，evidence_available:false。
- 全量 npm test 0 fail；新增测试覆盖 operator、feed、profile、硬确认、脱敏、cursor、同页/最小记录门禁。

## 7. 风险与已知限制

- 任意 JS + 登录 profile 的 prompt injection / 账号操作风险；仅单用户本机、可信源、手动可见。
  HTTP 已不接受客户端 steps/JS，但页面内任意 JS 仍可绕过危险动作确认——不是安全边界。
- WeChat 验证/登录形态与 DOM 选择器可能变化（#js_content/#activity-name 等），改版会读取失败。
- UIBE 结构可能变化，且 robots 未确认前默认不自动采集。
- 服务重启后 waiting_login/waiting_human 不能续跑，标 failed（OPERATOR_RESTART）。
- SSRF 仅字面私网拦截，未防 DNS rebinding。
- 30 天后证据不可用；下游不能假设 evidence_ref 永久有效。
- 公司档案写入不进增量（无 write_audit 行），只在快照可见。
