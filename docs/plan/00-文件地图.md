# 00 · 文件地图与系统关系（v2 现状）

> 用途：先让"这个文件夹里到底有什么"变得一眼可见，再谈搬到哪。
> 统计时间：2026-10-24。源码 54 个文件、约 3,000 行；运行时数据 104 MB。

---

## 1. 一眼看懂的三层结构

```
职向/
├─ 源码（会被 git 管理，约 1 MB）
│  ├─ 根目录 24 个 .mjs / .html / .js   ← 目前是平铺的，最乱的地方
│  ├─ recruit/  9 个文件（招聘采集）
│  ├─ docs/     5 篇旧文档 + 3 份示例 + 4 张截图
│  └─ 测试 4 个文件 + 1 个 mock 服务
│
├─ data（不应进 git，约 104 MB）
│  └─ .data/users/<账号>/.data/platform-profiles/  ← 103.7 MB，1043 个 Edge 缓存文件
│
└─ node_modules（75.7 MB，可重装）
```

**结论：代码只有 ~1 MB，真正让文件夹"变重"的是 `.data` 里的浏览器资料目录。**

## 3. 依赖关系图（谁引用谁）

```
                        ┌───────────────┐
                        │  server.mjs   │  ← 16 个端点
                        └──┬──┬──┬──┬───┘
        ┌──────────────────┘  │  │  └──────────────────┐
        ▼                     ▼  ▼                     ▼
  accounts.mjs          agent.mjs  model-settings   recruit/api.mjs
                              │        │                 │
                    ┌─────────┴──┐     ▼                 ▼
                    ▼            ▼  providers.mjs   recruit/{store,sources,
              context.mjs   workflow.mjs             collect,schedule,fetch}
                    ▲
              api-model.mjs ──→ tool-policy.mjs
                    │      └──→ proxy-fetch.mjs
                    ▼
              diag.mjs ──→ providers.mjs

  platforms.mjs ← server.mjs（平台打开/读取）
  keyvault.mjs  ← server.mjs（每个租户一个）
```

**问题：**

1. `server.mjs` 同时依赖业务、模型、采集、浏览器，是唯一的"总装点"——任何改动都要动它。
2. `api-model.mjs` 既做模型协议，又内联了 `career_platform_*`、`career_public_search`、`career_company_research`、`career_recruit_events` 四个工具的业务实现。
3. `tool-policy.mjs` 里的参数表、`api-model.mjs` 里的 `API_TOOLS`、`platform-mcp.mjs` 里的工具描述，**三处重复维护**。
4. `ui-model.js` 与 `index.html` 是"补丁关系"，不是清晰分层。

## 4. 数据目录（`.data`）明细

| 路径 | 大小 | 内容 | 是否该进项目 |
| --- | --- | --- | --- |
| `.data/users/<id>/.data/platform-profiles/` | **103.7 MB / 1043 文件** | Edge 浏览器资料（含小红书缓存、Cookie、GPU 缓存） | ❌ 应移到用户数据目录 |
| `.data/users/<id>/.data/recruit.db` | 0.35 MB | 79 场活动 | ❌ 运行时数据 |
| `.data/users/<id>/.data/secrets.enc.json` + `vault.key` | 很小 | 加密 Key | ❌ 绝不能进 git |
| `.data/users/<id>/.data/model-settings.json` | 很小 | 模型配置 | ❌ |
| `.data/accounts.json`、`首次登录.txt` | 很小 | 账号 | ❌ |
| `.data/server.log`、`server-error.log` | 很小 | 日志 | ❌ |

> 共享包里如果把 `.data` 一起压缩，等于把简历、密码哈希、加密密钥、平台登录态一起发出去。**必须默认外置并排除。**

## 5. 结构性问题清单（这次要解决的）

| # | 问题 | 证据 | 解决方向 |
| --- | --- | --- | --- |
| S1 | 根目录平铺 24 个文件，看不出分层 | 上面的清单 | 按 `src/{server,agent,model,tools,recruit,web}` 重组 |
| S2 | `server.mjs` 上帝文件 | 275 行、16 端点、单行数百字符 | 拆成 routes + tenant + http |
| S3 | 工具定义三处重复 | `API_TOOLS` / `tool-policy` / `platform-mcp` | 统一 `tools/registry.mjs` |
| S4 | 业务工具写进模型层 | `api-model.mjs` 里 4 个工具实现 | 模型层只负责协议，工具放 `tools/` |
| S5 | 前端靠补丁覆盖 | `ui-model.js` 覆盖 `showModelSettings` | 拆 HTML/JS/CSS，取消覆盖 |
| S6 | 运行时数据混在项目内 | 104 MB `.data` | 默认外置到 `%LOCALAPPDATA%\ZhiXiang` |
| S7 | 缺"技能/记忆"概念 | 只有一段 `session.memory` 字符串 | 新增 `skills/` 与三层记忆 |
| S8 | 采集适配器全在一个文件 | `sources.mjs` 313 行 | 每校一个适配器 + 注册表 |
| S9 | 无活动生命周期 | 只有 `verified` | 增加 active/cancelled/possibly_removed |
| S10 | 文档与代码混杂 | docs/ 5 篇 + 根目录 2 篇 | docs 索引 + archive/examples/assets |
| S11 | 无版本控制 | `fatal: not a git repository` | 已建 git 基线（见 03） |
| S12 | 无统一验收脚本 | 只有 `npm test` | 增加 `npm run check`（测试+体检+采集 smoke） |
