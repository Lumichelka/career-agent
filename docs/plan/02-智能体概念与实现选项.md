# 02 · 智能体概念：Tool、Skill、Memory 到底是什么

> 你的问题："我需要明白我使用了哪些 tool、有哪些 skill、记忆是什么，或者如何用其他方案实现智能体操作？"
> 短答：**你不需要会写它们，但必须知道它们的存在和边界**——否则出了问题只能看到一句"连接失败"。

---

## 1. 先给结论

| 概念 | 一句话 | 你需要知道什么 | 你不需要知道什么 |
| --- | --- | --- | --- |
| Tool（工具） | 模型能"动手"的函数 | 它能不能读你的电脑/网页、会不会改数据 | 具体 HTTP 怎么发、参数怎么校验 |
| Skill（技能） | 一套"办事流程" | 它什么时候被触发、产出什么、边界在哪 | 提示词怎么写、模型怎么选 |
| Memory（记忆） | 它记住了你什么 | 记住了哪些事实、存在哪、怎么删 | 向量库、检索算法 |

**一句话：把智能体想成一个实习生——工具是他的手，技能是他的培训手册，记忆是他的笔记本。你要管的是"他能不能碰这个""他记的东西对不对"，不是"他的神经怎么连"。**

---

## 2. Tool：模型能调用的函数

### 2.1 类比

你让实习生"去查一下这周川大的宣讲会"。他得有：
- 一台能上网的电脑（浏览器工具）
- 一个能查公司信息的渠道（搜索工具）
- 一个能打开你简历的权限（文件工具）

这些就是 tool。每个 tool 都有：

```
名称 + 说明（模型据此决定用不用）
参数 schema（必须传什么）
权限（只读 / 可写）
返回（成功数据 / 失败原因）
```

### 2.2 本项目现有与规划中的工具

| 工具 | 干什么 | 权限 | 现状 |
| --- | --- | --- | --- |
| `career_recruit_events` | 查本机活动库、排班 | 只读 | ✅ 已有 |
| `career_company_research` | 查公司公开信息 | 只读 | ✅ 已有（需搜索服务） |
| `career_public_search` | 公开搜索 | 只读 | ✅ 已有（需 SearXNG） |
| `career_platform_status/search/read` | 读 BOSS/小红书 | 只读 | ✅ 已有（本人登录） |
| `resume.list/get` | 读简历版本 | 只读 | ⏳ 规划 |
| `resume.save_version` | 存新简历版本 | **可写** | ⏳ 规划（需确认） |
| `application.upsert` | 记录投递 | **可写** | ⏳ 规划（需确认） |
| `memory.read/write` | 读写长期记忆 | 读/写 | ⏳ 规划（写入需确认） |

### 2.3 现在的问题

工具定义散在三个文件里：

- `api-model.mjs` 的 `API_TOOLS`（给模型的 schema）
- `tool-policy.mjs` 的参数白名单（校验）
- `platform-mcp.mjs` 的 MCP 工具描述（Codex 模式）

**三处维护 = 迟早不一致。** v3 合并成一份注册表，并自动生成"能力面板"（设置页里能看到"这个智能体现在会做什么、不会做什么"）。

## 3. Skill：一套可复用的办事流程

### 3.1 为什么需要 skill

同样是"排行程"，你可能希望：
- 先看他有没有时间冲突
- 再算通勤
- 再按"必须去/可选去"排序
- 最后导出日历

这套步骤不该每次让模型自由发挥，而应固化成技能。技能 = **步骤 + 约束 + 输出格式 + 验收清单**。

### 3.2 本项目的四个技能

| 技能 | 什么时候用 | 产出 | 明确不做 |
| --- | --- | --- | --- |
| `schedule-planner` | "这周有什么""帮我排一下" | 按天行程 + 冲突 + ICS | 不编造场次 |
| `company-research` | "这家公司怎么样" | 行业/规模/校招/口碑 + 来源 | 不推算录用率 |
| `resume-tailoring` | "按这个 JD 改简历" | 新版本 + 差异 + 缺口 | 不编造经历/数字 |
| `interview-prep` | "准备面试" | 流程预测 + 题库 + 追问 | 不承诺通过 |

### 3.3 技能长什么样（目录即契约）

```
src/skills/resume-tailoring/
├─ SKILL.md      # 何时触发、步骤、边界
├─ prompt.md     # 给模型的约束（可版本化）
├─ schema.json   # 输出结构（可校验）
└─ checklist.md  # 验收：来源？编造？覆盖 JD？
```

这样你可以**只改一个技能**而不动整个系统；也可以把技能单独导出，给 Claude/Codex 用（参考产品"录阶"就是这么做的，见 04 文档）。

## 4. Memory：它记住了你什么

### 4.1 现在只有"一段字符串"

`session.memory` 是每轮由模型覆写的一段文字（最多 5000 字）。问题：

- 只活在单个会话里，换对话就丢；
- 模型可能把猜测写进去；
- 你无法查看"它到底记住了什么"。

### 4.2 v3 的三层记忆

| 层 | 例子 | 存哪 | 写入规则 |
| --- | --- | --- | --- |
| L1 会话记忆 | "这次只看成都" | 会话 JSON | 每轮自动，会话结束即止 |
| L2 长期画像 | "2027 届、金融学、想去成都/上海、会 SQL" | `profile.json` | **用户确认后**才写；面板可删 |
| L3 任务记忆 | "这次用了哪些工具、查到什么、生成了什么" | 任务记录 | 自动，可追溯 |

### 4.3 记忆的边界

- 不记：身份证、手机号、平台密码、Cookie、完整简历原文（原文在附件里，按需读取）。
- 可删：面板上逐条删除，或一键清空。
- 可导出：换电脑时带走。

### 4.4 为什么你该关心

因为**记忆错了比没记忆更糟**：如果它记住"你想去北京"，之后所有推荐都会偏。所以 v3 的规则是：**推测不写、确认才写、面板可见**。

## 5. 三者怎么配合（走一遍）

```
你说："这周成都有什么宣讲会，帮我排一下，顺便看看那家公司"
        │
        ▼
① 计划：查活动 → 排班 → 调研公司 → 汇总
        │
        ▼
② 工具（手）：
   recruit.query({city:'成都', days:7})      ← 只读
   company.research({company:'XX银行'})      ← 只读
        │
        ▼
③ 技能（流程）：
   schedule-planner  → 冲突/通勤/排序
   company-research  → 结构化简报 + 来源
        │
        ▼
④ 交付：行程表 + ICS + 公司简报（每条带来源）
        │
        ▼
⑤ 记忆：问你要不要把"关注成都、金融方向"记到长期画像
```

## 6. 为什么现在"感觉不到"这些

因为 v2 把它们都塞进了代码：

- 工具清单只在提示词字符串里；
- 技能没有独立文件，混在 `agent.mjs` 的系统提示词里；
- 记忆只有一个 `session.memory` 字段。

v3 要把它们**变成看得见的东西**：

- 设置页 →「能力」：工具清单（只读/可写）、技能清单、记忆清单；
- 对话里 → 每次调用工具时显示"正在查活动库（只读）"；
- 写操作 → 弹出预览"将保存为新简历版本，确认？"

## 7. 实现智能体的五种方案

| 方案 | 怎么实现 | 多端 | 采集能力 | 改动成本 | 适合 |
| --- | --- | --- | --- | --- | --- |
| **A. 自研循环（当前）** | 自己写 plan→act→review，工具用函数注册 | 中（自己做前端） | **强**（能开浏览器/抓接口） | 低（已在手） | **本项目** |
| B. MCP 化 | 把工具做成 MCP Server，用 Claude/ChatGPT/自研客户端连 | **强**（客户端自带） | 强（服务端跑） | 中（要改传输层） | 想"随处可用" |
| C. 图编排（LangGraph/Agno） | 节点=步骤，边=条件，状态机 | 中 | 中 | 高（要重写） | 流程复杂、多人协作 |
| D. 低代码平台（Dify/Coze） | 拖拽工作流 + 插件 | **强** | 弱（跑不了登录浏览器） | 中（要搬） | 只做对话演示 |
| E. 纯提示词 | 一份说明书 + 手动操作 | 强 | 无 | 极低 | 一天交作业 |

### 推荐组合

```
主链路：A（自研循环）——因为采集必须能开浏览器、抓隐藏接口
增强：B（把 recruit/查询/排班 暴露成 MCP）——手机端/其他客户端可用
不选：C/D 重写——性价比低；E 作为"没有电脑时"的兜底
```

---

## 8. 你作为使用者，只需要记住三句话

1. **工具决定它能不能碰你的东西**——只读的工具随便用，可写的必须先确认。
2. **技能决定它办事靠不靠谱**——同一个模型，有技能和没技能差别很大。
3. **记忆决定它会不会越用越懂你，也决定它会不会记错你**——所以必须能看、能删。

## 9. 下一步

如果这套分层你认可，Phase 1 就会先把"工具注册表 + 能力面板"做出来，让你在界面上直接看到：

- 这个智能体有哪些工具（哪些只读、哪些会写）
- 有哪些技能（什么时候触发）
- 记住了什么（可删）

然后再逐个实现技能，而不是一次性堆功能。
