## 2. 分支模型（简单版，适合个人 + 小组）

| 分支 | 用途 | 规则 |
| --- | --- | --- |
| `main` | 随时能跑的稳定版 | 只接受来自 `dev` 的合并；打 tag |
| `dev` | 下一个版本的集成 | 功能分支合并到这里 |
| `feat/<模块>` | 单个功能（如 `feat/recruit-sources`） | 从 `dev` 切，完成后合回 |
| `docs/<主题>` | 文档 | 可直接合 `main` |
| `fix/<问题>` | 修 bug | 从 `main` 切，合回 `main` 和 `dev` |

日常：

```bash
git switch dev
git switch -c feat/recruit-sichuan
# 写代码、跑测试
git add -A && git commit -m "feat(recruit): add sichuan universities adapters"
git switch dev && git merge --no-ff feat/recruit-sichuan
git switch main && git merge --no-ff dev && git tag -a v3.0.0-m2 -m "milestone 2"
```

## 3. 提交信息规范

```
<类型>(<范围>): <一句话>

类型：feat 新功能 / fix 修复 / refactor 重构 / docs 文档 / test 测试 / chore 杂务
范围：recruit / sources / wechat / source-check / agent / skills / model /
      web / ui / server / platform / company / resume / interview / feed /
      mcp / memory / tools / deploy / docs / ci / acceptance / adr / plan /
      research / skill
```

`scripts/check-commit-msg.mjs` 会检查类型、范围白名单和首行格式。CI 对推送范围里的每个非合并提交执行检查；本地可跑 `npm run check:commit` 检查当前 HEAD。

例子：

- `feat(recruit): add 四川大学双选会适配器`
- `refactor(server): split routes into src/server/routes`
- `fix(model): keep api key after restart`
- `docs(plan): add v3 restructure plan`

**好处**：以后你可以用 `git log --oneline --grep feat(recruit)` 快速回看"采集这块改过什么"。

## 4. 测试门禁（合并前必须过）

```bash
npm test          # 自动化测试（全部通过）
npm run check     # 规划中：测试 + 体检 + 采集 dry-run + 页面冒烟
```

建议在每个 Phase 结束时：

1. `npm test` 全绿；
2. 双击启动，手动走一遍三条主路径；
3. 打 tag（如 `v3.0.0-phase0`）；
4. 在 `docs/plan/CHANGELOG.md` 记一句。

## 5. 数据与代码分离（关键）

### 5.1 现在的问题

- `.data` 在项目里，104 MB，且含简历/账号/密钥；
- 一旦有人 `git add .` 或打包分享，隐私就出去了；
- 浏览器缓存（103 MB）每天都在变，会让 git 状态一团糟。

### 5.2 v3 方案

```
代码：F:\职向                （git 仓库，约 1 MB）
数据：%LOCALAPPDATA%\ZhiXiang （默认，可配置）
      或 F:\职向-data
```

实现方式：

- `server.mjs` 启动时读取 `CAREER_DATA_DIR`，默认 `%LOCALAPPDATA%\ZhiXiang`；
- 首次启动如果发现旧 `.data`，提示"检测到旧数据，是否迁移？"（复制，不删除）；
- `.gitignore` 已忽略 `.data/`、`data/`，双保险。

### 5.3 备份

```bash
# 只备份数据（推荐）
robocopy "%LOCALAPPDATA%\ZhiXiang" "D:\backup\zhixiang-%date%" /MIR

# 或整包（不含 node_modules）
```

**永远不要把数据目录提交到 git，也不要在分享包里带上它。**

## 6. 回滚与对比

| 场景 | 做法 |
| --- | --- |
| 改坏了想回到上个版本 | `git switch main` 或 `git checkout <tag>` |
| 只想撤一个文件 | `git restore <file>` |
| 想看某次改了什么 | `git show <commit> --stat` |
| 想对比两个版本 | `git diff v2.0.0..HEAD -- src/recruit` |
| 实验性改动 | 新分支，不合就删；不要在主分支上试 |

> 只要数据目录不在 git 里，回滚代码不会影响你的简历、账号、采集库。

## 7. 与"测试"的配合

| 想测什么 | 怎么做 | 不影响什么 |
| --- | --- | --- |
| 新采集源 | `node recruit/cli.mjs collect --source <id> --limit 5` | 不动已有数据（同 id 会更新） |
| 新页面 | 起服务 → 开 `/recruit` | 不改数据库结构 |
| 新模型 | 设置页 → 一键体检 | 不改代码 |
| 新迁移 | 先备份 `recruit.db` → `node scripts/migrate.mjs` | 可回滚 |

## 8. 是否要放到 GitHub

| 选项 | 优点 | 注意 |
| --- | --- | --- |
| 只本地 | 零风险 | 换电脑要手动拷 |
| GitHub 私有仓库 | 备份、多人协作、Issue | 确保 `.gitignore` 生效；不要提交数据 |
| Gitee 私有 | 国内快 | 同上 |

**建议**：先本地跑通 Phase 0，再推私有仓库。推之前执行：

```bash
git ls-files | findstr /i ".data"    # 应该没有输出
git ls-files | findstr /i ".db"      # 应该没有输出
git ls-files | findstr /i "secret"   # 应该没有输出
```
