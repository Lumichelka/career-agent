# 27 · 公众号采集管线（#50）

> 日期：2026-10-27 ｜ 状态：已实现 ｜ 关联：docs/plan/19-平台与公众号.md、docs/plan/26-数据源核对与功能调整计划.md

## 1. 解决什么

原来的公众号是「粘一篇、记一篇」：10 个账号只有 4 篇文章，9 个账号为空，2 篇挂在「未归类公众号」，还有 1 条 example.com 演示数据。

现在把公众号当成一条可重复运行的管线：

```
账号发现/订阅 → 订阅页发现文章链接 → 抓正文 → 自动归属账号
              → 判断是否招聘、抽取活动/项目 → 去重 → 写入招聘库（带来源）
```

## 2. 四个环节

### 2.1 账号发现/订阅

- 账号来源仍是 9 个种子账号（accounts.mjs），支持别名与历史 biz（例如「西财就业」→「西财校招」）。
- 账号可以配置一个**公开订阅页**（学校就业网、公众号矩阵页、文章列表页等）：
  `POST /api/wechat/accounts/<id>/subscribe`，请求体 `{feedUrl}`。
- 同步时抓订阅页，提取 `mp.weixin.qq.com/s...` 文章链接，逐篇入库：
  `POST /api/wechat/accounts/<id>/sync` 或 `POST /api/wechat/sync`。
- 也可以粘贴来源页 HTML/正文或一行一条「账号 | 文章链接」清单做发现：
  `POST /api/wechat/discover`。

**边界**：微信账号历史文章接口需要登录态/客户端，公众号主页会要求验证；本项目不绕过验证。没有公开订阅页时，仍然可以用「粘贴文章链接/正文」逐篇导入。

### 2.2 文章自动归属

归属顺序（强 → 弱）：

1. 显式指定账号（导入时选择）；
2. 文章链接的 `__biz`，包含账号的历史 biz 别名；
3. 页面里的公众号昵称（`var nickname`、`data-nickname`、profile_nickname 等）；
4. 正文/标题里出现已知账号名（例如正文开头的「中山大学就业」）；
5. 学校全名 + 就业/校招语境（弱证据）。

都匹配不到时才落到「未归类公众号」；下次同步/打开旧库会重新尝试归属。种子账号自己的 `biz` 会在第一次成功归属后自动补上。

### 2.3 文章 → 活动/项目（带来源）

- 分析仍由 `analyze.mjs` 负责：判断是否招聘、抽活动草稿、抽参会单位。
- 只有同时满足「至少 1 个参会单位」+「合法开始时间」才自动写入招聘库，避免把月历、邀请函写成空活动。
- 写入字段：
  - 活动 `source_id = wechat:<accountId>`、`source_url = 文章链接`、`confidence = 0.6`、备注「公众号自动抽取，待核对」；
  - 项目 `source_id` 同上、`source_url = 文章链接`、`source_key` 稳定哈希。
- 手动补发：`POST /api/wechat/articles/<id>/publish`，或页面上的「生成活动/项目」。
- 批量补发：`node src/wechat/cli.mjs publish-all`。

### 2.4 去重

- **链接**：只保留文章定位必需的参数（`__biz/mid/idx/sn`），去掉协议差异、`chksm`、`scene`、`from`、hash 等；短链 `/s/<slug>` 去掉查询参数。
- **文章**：同账号下「标题 + 发布时间 + 内容指纹」相同视为同一篇；不同链接但同内容也会合并。
- **账号**：账号名归一（去空白/标点/「公众号/官微」后缀），同 biz 不重复建号。
- **活动/项目**：活动稳定 id + 同标题同开始时间去重；项目按 `(event_id, source_id, source_key)` 幂等。

### 2.5 演示数据清理

- 打开 `wechat.db` 时自动删除 `example.com/example.org/example.net/localhost` 的文章；
- `POST /api/wechat/purge-demo` 或 `cli purge-demo` 同时清理招聘库里来源为这些域名的活动；
- 空「未归类公众号」账号会被自动删除，不留空壳。

## 3. 数据表新增字段

`wechat_accounts`：`alias_biz`、`alias_names`、`feed_url`、`last_sync_at`、`last_sync_status`、`last_sync_error`。

`wechat_articles`：`nickname`、`biz`、`content_hash`、`dedupe_key`。

旧库启动时自动补列、归一化链接、合并重复行、清理演示数据并回填归属，不改业务数据。

## 4. 接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/wechat/accounts` | 账号 + 文章 + 统计（含订阅/待归属/演示数） |
| GET | `/api/wechat/articles` | 文章列表（含账号名） |
| POST | `/api/wechat/accounts` | 新增账号 |
| POST | `/api/wechat/accounts/<id>/subscribe` | 保存/取消订阅 |
| POST | `/api/wechat/accounts/<id>/sync` | 同步一个账号 |
| POST | `/api/wechat/sync` | 同步全部已订阅账号 |
| POST | `/api/wechat/discover` | 从来源页发现账号 |
| POST | `/api/wechat/articles/import` | 链接/正文导入 + 自动归属 + 自动发布 |
| POST | `/api/wechat/articles/<id>/publish` | 手动发布到招聘库 |
| POST | `/api/wechat/purge-demo` | 清理演示数据 |

## 5. 命令行

```bash
node src/wechat/cli.mjs report
node src/wechat/cli.mjs sync --publish
node src/wechat/cli.mjs import --url "https://mp.weixin.qq.com/s/..." --text "正文"
node src/wechat/cli.mjs discover --url "https://学校就业网/公众号栏目"
node src/wechat/cli.mjs publish-all
node src/wechat/cli.mjs purge-demo
```

## 6. 验收对照

| 验收 | 实现/测试 |
| --- | --- |
| 9 个空账号能抓到最近文章 | 订阅同步测试：9 个账号各 1 个订阅页，全部入库；重复同步不重复（tests/wechat-harvest.test.mjs） |
| 真实招聘文章带来源的活动/项目 | `publishArticle` 写 `source_id=wechat:<账号>` + 文章链接；导入自动发布与手动发布均有测试 |
| 0 条演示数据 | 启动迁移 + purge-demo；旧库升级测试断言 example.com 归零 |

## 7. 已知限制

- 微信账号历史文章必须登录/客户端；没有公开订阅页时无法自动列出「最近文章」，只能粘贴链接/正文或从学校来源页发现。
- 订阅页本身受 robots.txt 约束；被拒绝时记录 `last_sync_status=error`，不绕过。
- 自动写入的活动置信度 0.6，界面仍要求人工核对；没有参会单位的推文只保留文章与分析，不生成空活动。
