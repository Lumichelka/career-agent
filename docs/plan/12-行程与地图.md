# 12 · 地图与导出（排班已暂停）

> 目标：看完活动能直接导航，导出日历能在手机上提醒。
> **2026-10-25 新需求：暂时移除行程规划/冲突/通勤；地图链接与 ICS/CSV/MD 导出保留。**
> 设计原则：**不依赖 API Key 也能用**；有 Key 再升级真实路线。

---

## 1. 每场活动都有地图链接

`mapUrlFor(event)` 生成高德 URI：

```
https://uri.amap.com/search?keyword=<地点 学校 城市>&city=<城市>
```

- 不需要 Key、不需要登录；
- 手机点开直接唤起高德/浏览器；
- 地点缺失时退化为"学校 + 城市"搜索；
- 城市为"全国"时不带 `city` 参数。

出现位置：

| 位置 | 形式 |
| --- | --- |
| 工作台行程卡 | 「地图」链接 |
| 机会日历卡片 | 「地图 ↗」 |
| `.ics` 日历 | DESCRIPTION 里 `地图：<url>`；手机日历点地址也能导航 |
| `.csv` | 新增「地图链接」列 |
| `.md` 安排表 | 地点变成可点链接 |

---

## 2. 排班逻辑（已暂停）

> 以下冲突/通勤逻辑保留在 `schedule.mjs` 供导出使用，但 UI、工具和技能不再调用；等需求恢复时再启用。

- 同城时间重叠 → 时间冲突；
- 同城间隔小于估算通勤 → 赶场紧张；
- 同日异地 → 需取舍；
- 通勤估算来自校区坐标（直线 × 1.35 / 25km/h + 15 分钟缓冲）。

地图链接补上了"最后一公里"：估算告诉你赶不赶得上，链接告诉你怎么走。

---

## 3. 为什么不接高德路径 API

- 需要申请 Key、有配额与商用限制；
- 没有 Key 时若强行调用会失败，反而是倒退；
- 当前方案零配置、可离线生成链接，导出后手机端体验更好。

后续若需要"真实驾车/公交耗时"，可以加 `CAREER_AMAP_KEY`，只替换 `estimateTravel` 的数据源，界面不变。

---

## 4. 使用路径（≤3 步）

1. 工作台看未来 7 天 → 点「地图」确认位置；
2. 机会日历筛完整范围 → 导出 `.ics`；
3. 手机日历导入 → 到点提醒，点地址导航。

---

## 5. 验证

- 单元测试：地图 URL 编码、无城市参数、ICS/CSV/Markdown 均含地图；
- 工作台实测 73 条未来 7 天活动，全部带地图链接；
- 机会日历 90 条活动全部带地图链接；
- 页面无 JS 报错。

---

## 6. 已知边界

- 地图链接是"搜索地点"，不是"从当前位置导航"；
- 通勤时间仍是估算，不是实时路况；
- 冲突/通勤排班功能已暂停，当前只做日历与导出；
- 高德 URI 在部分 iOS 浏览器会先打开网页版，属正常。
