# 06 · 模块交付清单（按这个顺序做，每步你都能看到东西）

> 原则：**一次只交付一个模块**，每个模块都能独立验收、独立回滚。
> 每个模块完成后我会：① 给你截图/命令输出 → ② 对照验收项 → ③ 打一个 git tag → ④ 你确认后进下一个。

---

## 0. 交付节奏

```
M0 整理 → M1 数据 → M6 工具/能力面板 → M2 采集框架 → M4 生命周期
   → M5 行程 → M9 工作台 → M7 技能 → M8 记忆 → M10 公司调研
   → M11 简历/面试 → M12 多端
```

每个模块的"完成"标准写在下面。**没达标就不进入下一个**，避免又堆成一团。

## 2. 每次交付的固定动作

1. **先给你看**：截图或命令输出 + 一段"这次改了什么、没改什么"。
2. **对照验收**：逐条打勾；没过的说明原因。
3. **打 tag**：`v3.0.0-m0`、`v3.0.0-m1`……随时可回。
4. **等你确认**：你不点头，不进入下一个模块。

---

## 3. 如果中途想改方向

- 改需求：在 `docs/plan/01` 的需求表里增删一行，我调整后续模块；
- 改优先级：直接说"先做 M9"，我把依赖关系重排；
- 想暂停：当前模块完成后停下，已完成的 tag 保留。
