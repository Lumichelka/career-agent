## 4. 1.3 抓取与真实性

### 1.3.1 插件与失败反馈 ✅

- 一校一文件（`src/recruit/sources/*.mjs`），自动发现；
- 每个源记录 `last_run / last_status / last_count / last_error`；
- 「检查各源连通性」返回 HTTP 状态与耗时；
- 失败原因如实显示：中央财经超时、西南财大 robots、成都理工 412、电子科大需登录；
- 替代方案写进 `note` / `fallback`。

### 1.3.2 真实性 ✅

- 生命周期：`active / cancelled / possibly_removed`，连续 3 次未出现才标记“可能撤下”；
- 再次出现自动恢复；取消活动默认隐藏；
- 连续采集被 `limit` 截断时不误标缺失；
- 多源合并、置信度提升；
- 「复核来源」重新抓原链接比对；
- 每条活动保留来源链接、采集时间、置信度。

## 11. 5 分钟演示脚本

1. **今天**（30 秒）：打开 `/`，指统计卡、未来 7 天、招聘项目、导出 `.ics`。
2. **采集**（75 秒）：`/recruit` → 信息源 14 个 → 点采集 → 看新增/失败原因 → 「公众号/手动导入」粘贴一段推文正文 → 解析 → 保存 → 打开活动看来源、地图、环节标签。
3. **日历/项目**（45 秒）：切到月历 → 点日期 → 展开活动 → 添加一个招聘项目 → 导出 ICS。
4. **对话**（90 秒）：`/chat` 问“这周成都有哪些宣讲会” → 调用 `career_recruit_events` 按日历列活动与项目 → 再问“按这个 JD 改简历”。
5. **材料**（60 秒）：`/resume` → 简历版本 → 从对话保存 → 下载 Word → 投递阶段 → 面试准备题库与回答。
6. **可靠性与回退**（30 秒）：`npm test` 109 项；`git tag` 列表；一条命令回退。

## 12. 已知缺口（按优先级）

1. 电子科大/成都理工等校适配；
2. BOSS 强风控下的稳定读取（当前靠 watchdog + 系统浏览器兜底）；
3. 公众号批量/自动发现（当前是链接/正文导入）；
4. 语音模拟面试（题库与回答已落库）。

> 这些缺口都不影响现有演示：页面会明确显示“未接入/未公布”，不会把缺失伪装成有数据。
