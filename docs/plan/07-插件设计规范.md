# 07 · 插件设计规范（信息源 / 工具 / 技能）

> 这份规范解决"每加一所学校就要改一个大文件"的问题。
> 目标：**新增一个信息源 = 新增一个文件；新增一个工具 = 新增一个文件；新增一个技能 = 新增一个目录。**

---

## 1. 三个扩展点

| 扩展点 | 解决什么 | 放哪 | 数量级 |
| --- | --- | --- | --- |
| 信息源 Source | 从某校某栏目取活动 | `src/recruit/sources/<id>.mjs` | 10–30 个 |
| 工具 Tool | 智能体能做的动作 | `src/tools/<name>.mjs` | 10–15 个 |
| 技能 Skill | 一套办事流程 | `src/skills/<id>/` | 4–6 个 |

三者关系：**技能决定"怎么做事"，工具提供"能做的事"，信息源是工具背后的数据来源。**

---

## 2. 信息源插件（Source）

### 2.1 契约

```js
// src/recruit/sources/sufe.mjs
export default {
  id: 'sufe-xjh',                 // 全局唯一，短横线
  name: '上海财经大学 · 宣讲会',
  school: '上海财经大学',
  city: '上海',
  category: '财经强校',            // 四川双一流 / 财经强校 / 双选会平台 / 其他
  channel: '就业信息网',
  kind: '宣讲会',                  // 默认类型，可被单条覆盖
  mode: 'json',                   // static | json | browser | rss | manual
  enabled: true,
  listUrl: 'https://career.sufe.edu.cn/...',
  notes: '匿名每页最多 10 条，需要翻页',

  // 抓列表：返回 SourceItem[]
  async list(ctx) {
    const res = await ctx.fetch(this.listUrl, {method: 'POST', body: '{}', headers: {...}});
    const json = JSON.parse(res.text);
    return json.data.list.map(r => ({
      title: r.xjhzt,
      company: r.dwmc,
      startAt: `${r.jbrq}T${r.jbsjdmc.slice(0,5)}:00+08:00`,
      venue: r.cddz,
      city: r.szsmc,
      url: `https://career.sufe.edu.cn/career/xjhxx/view/${r.xjhid}`,
      raw: r
    }));
  },

  // 可选：抓详情补字段
  async detail(item, ctx) { return {}; },

  // 可选：健康检查（默认请求 listUrl）
  async health(ctx) { return {ok: true}; }
};
```

### 2.2 SourceItem 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | ✅ | 活动名称 |
| `startAt` | ✅ | ISO 8601，带 `+08:00` |
| `endAt` | | 没有就按 +90 分钟 |
| `company` | | 单位名 |
| `venue` / `address` | | 地点 |
| `city` | | 城市（会归一化） |
| `url` | ✅ | 原文链接 |
| `kind` | | 覆盖默认类型 |
| `industry` / `companySize` | | 有就填 |
| `applyMode` / `applyUrl` | | 网申/现场/邮箱 |
| `interviewStage` / `notice` | | 面试环节、注意事项 |

### 2.3 错误约定

适配器**不要自己吞错**，抛出带分类的错误：

```js
throw new SourceError('blocked', '站点返回 403，可能需要浏览器模式');
// kind: blocked | login_required | changed | network | empty | parse
```

采集器统一转成 `runs` 记录 + 健康面板展示。

### 2.4 注册

`src/recruit/sources/index.mjs` 自动扫描：

```js
import {readdirSync} from 'node:fs';
const modules = readdirSync(new URL('.', import.meta.url))
  .filter(f => f.endsWith('.mjs') && f !== 'index.mjs')
  .map(f => import(new URL(f, import.meta.url)));
export const SOURCES = (await Promise.all(modules)).map(m => m.default).filter(Boolean);
```

### 2.5 新增一所学校的步骤

1. 复制一个同 `mode` 的适配器；
2. 填 `id/meta/listUrl`；
3. 写 `list()` 的解析（用真实页面调试）；
4. 加一个 fixture 测试（见第 5 节）；
5. 跑 `node scripts/source-check.mjs --source <id>`。

**不改任何其他文件。**

## 3. 工具插件（Tool）

### 3.1 契约

```js
// src/tools/recruit-query.mjs
export default {
  name: 'recruit.query',
  title: '查询线下招聘',
  description: '按城市/时间/学校/类型查询本机活动库，返回活动与来源。',
  parameters: {
    type: 'object',
    properties: {
      city: {type: 'string'},
      days: {type: 'number', minimum: 1, maximum: 90},
      school: {type: 'string'},
      kind: {type: 'string', enum: ['宣讲会','双选会','就业指导','招聘信息','其他']}
    },
    additionalProperties: false
  },
  permission: 'read',        // read | write
  timeoutMs: 5000,
  async run(args, ctx) {
    const events = ctx.store.listEvents({...});
    return {ok: true, count: events.length, events};
  }
};
```

### 3.2 权限与确认

| 权限 | 行为 |
| --- | --- |
| `read` | 直接执行，界面显示"读取中" |
| `write` | **先返回预览**，用户点确认后才落库 |

写工具的 `run` 分两段：

```js
async preview(args, ctx) { return {summary:'将保存为新简历版本', payload:{...}}; }
async commit(preview, ctx) { ... }
```

### 3.3 统一错误

```js
{ok:false, code:'UNAVAILABLE'|'INVALID_ARGS'|'NOT_FOUND'|'TIMEOUT'|'DENIED', message}
```

模型拿到错误后按提示换策略，而不是重复调用。

### 3.4 注册与能力面板

`src/tools/index.mjs` 自动收集；`GET /api/capabilities` 返回：

```json
{"tools":[{"name":"recruit.query","permission":"read","title":"查询线下招聘"}],
 "skills":[{"id":"schedule-planner","enabled":true}]}
```

设置页「能力」直接渲染这份数据，**代码即文档**。

## 4. 技能插件（Skill）

### 4.1 目录

```
src/skills/schedule-planner/
├─ SKILL.md        # 元信息 + 步骤 + 边界（人读）
├─ prompt.md       # 给模型的约束（可版本化）
├─ schema.json     # 输出结构（可校验）
└─ checklist.md    # 验收清单
```

### 4.2 SKILL.md 模板

```markdown
---
id: schedule-planner
name: 行程规划
triggers: ["排行程", "这周有什么", "冲突"]
tools: [recruit.query, recruit.schedule]
writes: false
version: 1
---

# 何时使用
用户想按天/周查看线下招聘，或需要判断是否赶得上。

# 步骤
1. 解析城市、时间范围、学校（缺省用画像）
2. 查询活动
3. 计算冲突与通勤
4. 输出：按天表格 + ICS 下载 + 来源

# 边界
- 不编造场次；没有数据就说没有
- 通勤是估算，注明"请用地图复核"
```

### 4.3 加载与执行

```js
const skill = await loadSkill('schedule-planner');
const prompt = [skill.prompt, context, userMessage].join('\n\n');
const result = await agent.run({tools: skill.tools, schema: skill.schema, prompt});
validate(result, skill.schema);
```

技能**只声明能用哪些工具**，不能越权；`writes:false` 的技能无法调用写工具。

## 5. 测试规范

| 插件类型 | 测什么 | 放哪 |
| --- | --- | --- |
| Source | 用真实 HTML/JSON 片段解析出正确字段 | `tests/fixtures/<id>.html` + `sources.test.mjs` |
| Tool | 参数校验、权限、错误分支 | `tests/tools.test.mjs` |
| Skill | schema 校验、工具白名单、边界 | `tests/skills.test.mjs` |

示例：

```js
test('sufe 解析', async () => {
  const source = (await import('../src/recruit/sources/sufe.mjs')).default;
  const html = await readFile('tests/fixtures/sufe.json', 'utf8');
  const items = await source.parseForTest?.(html) ?? source.listFromJson(JSON.parse(html));
  assert.equal(items[0].company, '中国光大银行股份有限公司上海分行');
});
```

> 适配器为了可测试，把"解析"与"请求"分开：`parse(payload)` 纯函数，`list(ctx)` 负责取数据再调 `parse`。

## 6. 版本与兼容

| 对象 | 规则 |
| --- | --- |
| Source `id` | 一旦发布不改名；学校改名用 `alias` 字段 |
| 活动 `id` | `sha1(school|title|startAt|venue)`，保持稳定 |
| 数据库 schema | `PRAGMA user_version`；迁移脚本单向前进，先备份 |
| Tool `name` | `域.动作`，如 `resume.save_version` |
| Skill `version` | 输出结构变化时 +1，旧任务记录保留 |
