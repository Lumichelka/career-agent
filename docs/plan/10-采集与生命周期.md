## 3. 源健康：失败要能说清楚

每个源在数据库里记录：

| 字段 | 含义 | 界面 |
| --- | --- | --- |
| `last_run` | 最近一次采集时间 | 源卡片「最近采集」 |
| `last_status` | `connected / list_only / needs_login / blocked_robots / network_error / empty / disabled`；旧库的 `ok`/`success` 映射 `connected`，`error`/`failed`/`timeout` 映射 `network_error`，`blocked`/`disallowed` 映射 `blocked_robots`，`login_required` 映射 `needs_login`，未知值按 `network_error` | 卡片标签颜色与中文原因 |
| `last_count` | 本次抓取条数（兼容字段，等同 `last_fetched`；新增/更新分别看 `last_created`/`last_updated`） | 源卡片 |
| `last_error` | 失败原因 | 卡片说明 |
| `failure_streak` | 连续失败次数：成功（connected/empty/list_only）清零，其余失败 +1；disabled 不参与采集 | 源卡片「连续失败 N 次」 |

### 3.1 七个状态的触发条件

| 状态 | 触发条件 | 来源表文案 |
| --- | --- | --- |
| `connected` | 列表解析到活动，且项目阶段成功；源明确不支持项目时只要求列表成功 | 已连通 |
| `empty` | 页面可访问，但列表没有解析到活动 | 暂无活动 |
| `list_only` | 列表解析到活动，但声明了项目能力的源项目阶段没有成功 | 仅列表 |
| `needs_login` | 源要求登录或人工确认，未自动采集 | 需登录 |
| `blocked_robots` | robots.txt 禁止或站点明确拦截 | 被站点拦截 |
| `network_error` | 网络、解析或未知错误 | 网络或解析失败 |
| `disabled` | 源未启用，不参与默认采集 | 未接入 |

`connected` 就是规格里的“ok”：只有列表解析到活动 **且** 项目阶段成功（或该源明确不支持项目）时才使用，`last_count` 记列表解析数。`list_only` 只说明活动已入库、项目阶段没成，不能当成项目成功；它在连续失败计数里按“活动列表成功”处理，但界面仍显示“仅列表”。旧库状态按 `ok`/`success` → `connected`、`error`/`failed`/`timeout` → `network_error`、`blocked`/`disallowed` → `blocked_robots`、`login_required` → `needs_login` 读取，未知值按 `network_error`。

另外提供「检查各源连通性」（`probe`），一次性 GET 每个源的列表页，返回 HTTP 状态/耗时/原因，用于判断是站点挂了还是解析坏了。

## 4. 活动生命周期

每条活动现在有：

| 字段 | 说明 |
| --- | --- |
| `status` | `active` / `cancelled` / `possibly_removed` |
| `first_seen_at` / `last_seen_at` | 第一次/最近一次在来源里看到 |
| `missing_runs` | 连续多少次成功采集没再出现 |
| `cross_sources` | 收录过这条活动的所有来源 |
| `interview_stage` | 招聘环节：`面试` / `笔试` / 空（未公布） |
| `interview_type` | 面试类型：无领导小组讨论 / 半结构化 / 结构化 / 群面 / 单面 / 笔试 / 空 |

> 环节与类型从标题、备注、详情原文里提取（`extractInterview`），识别不到就留空，不猜测。界面上有值才显示标签，导出 CSV/ICS/Markdown 也会带上。

### 规则

1. **取消**：标题或正文含「取消 / 暂停举办 / 活动取消」→ `cancelled`，默认列表和日历排除，但仍保留在库里。
2. **可能撤下**：单源活动连续 **3 次**成功采集未出现 → `possibly_removed`；再次出现立刻恢复 `active` 并清零。
3. **截断保护**：如果本次列表被 `limit` 截断（解析条数 ≥ 上限），**不做缺失标记**，避免把"没抓全"当成"撤下"。
4. **多源合并**：同一活动被两个来源收录 → `cross_sources` 合并、置信度 +0.08；多源活动不参与单源缺失标记。
5. **复核**：界面上的「复核来源」会重新抓原链接并比对标题，结果写入 `verified`。

### 活动与招聘项目（一对多）

一场双选会/宣讲会可以挂多个招聘项目，存在独立表 `event_projects`：

```sql
event_projects(
  id, event_id, company, title, positions, requirements,
  apply_mode, apply_url, source_url, notes,
  source_id, source_key, status, confidence,
  first_seen_at, last_seen_at, missing_runs, raw_text,
  created_at, updated_at, platform, city, fetched_at
)
```

| 字段 | 说明 |
| --- | --- |
| `id` / `event_id` | 项目主键 / 所属活动 `events.id` |
| `company` / `title` | 单位 / 项目或岗位名称；两者至少一项 |
| `positions` / `requirements` | 岗位、人数、薪资 / 学历、专业等要求 |
| `apply_mode` / `apply_url` | 投递方式（现场/网申）/ 投递链接 |
| `source_url` / `notes` | 项目原文链接 / 展位、行业等备注 |
| `source_id` | 自动项目来源 id；手工项目的 `source_id` 为空，不参与自动项目同步，也不会被自动清理 |
| `source_key` | 源内稳定键；与 `event_id`、`source_id` 组成唯一键，重复采集按它幂等 |
| `status` | `active` / `removed`；自动项目连续 3 次未出现才变 `removed` |
| `confidence` | 项目置信度，默认 0.8，来源可覆盖 |
| `first_seen_at` / `last_seen_at` | 第一次入库时间 / 最近一次同步检查时间；项目出现时更新，连续缺失检查时也会写本次检查时间，仅用于排查 |
| `missing_runs` | 连续未出现次数；每次未出现 +1，出现即清零 |
| `raw_text` | 源记录原文片段（截断到 4000 字），供复核 |
| `created_at` / `updated_at` | 创建 / 最近更新 |
| `platform` / `city` / `fetched_at` | 平台岗位补充字段 / 城市 / 最近抓取时间 |

- 唯一索引 `(event_id, source_id, source_key)`；手工项目不参与自动项目同步；
- 项目不参与活动生命周期与缺失标记；
- 项目在 `/recruit` 月历的活动卡片里增删；
- 详细设计见 [20 日历与招聘项目](20-日历与招聘项目.md)。

### 界面标签

- 红色「可能撤下」：连续未出现；
- 红色「已取消」：来源明确取消（默认不显示）；
- 绿色「多源收录」：≥2 个来源收录；
- 「已复核」/「待复核」：人工复核状态。

## 5. 怎么新增一所学校

1. 复制一个同 `mode` 的文件改名，例如 `uestc.mjs`；
2. 填 `id/name/school/city/category/listUrl/mode`；
3. 写 `parseList(html|json, source)`（浏览器模式暂不需要）；
4. 在 `tests/sources.test.mjs` 的注册表断言会自动覆盖；
5. 跑 `node src/recruit/cli.mjs collect --source <id> --limit 5` 验证。

不改 `collect.mjs`、`api.mjs`、前端。

## 6. 失败时怎么办（作业 1.3.1）

```
静态解析失败 → 找隐藏 JSON 接口 → 浏览器模式 → 人工转发链接
```

每个源的 `note` / `fallback` 字段写明备用通道。例如中央财经：

> 本次测试连接超时（可能是站点侧 IP 限制或网络策略），需要备用通道。
> 备用：官方微信公众号 + 人工转发链接解析。
