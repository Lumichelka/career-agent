## 3. 源健康：失败要能说清楚

每个源在数据库里记录：

| 字段 | 含义 | 界面 |
| --- | --- | --- |
| `last_run` | 最近一次采集时间 | 源卡片「最近采集」 |
| `last_status` | `ok / empty / blocked / error / disabled` | 卡片标签颜色 |
| `last_count` | 本次新增条数 | 源卡片 |
| `last_error` | 失败原因 | 卡片说明 |

另外提供「检查各源连通性」（`probe`），一次性 GET 每个源的列表页，返回 HTTP 状态/耗时/原因，用于判断是站点挂了还是解析坏了。

## 4. 活动生命周期

每条活动现在有：

| 字段 | 说明 |
| --- | --- |
| `status` | `active` / `cancelled` / `possibly_removed` |
| `first_seen_at` / `last_seen_at` | 第一次/最近一次在来源里看到 |
| `missing_runs` | 连续多少次成功采集没再出现 |
| `cross_sources` | 收录过这条活动的所有来源 |

### 规则

1. **取消**：标题或正文含「取消 / 暂停举办 / 活动取消」→ `cancelled`，默认列表和日历排除，但仍保留在库里。
2. **可能撤下**：单源活动连续 **3 次**成功采集未出现 → `possibly_removed`；再次出现立刻恢复 `active` 并清零。
3. **截断保护**：如果本次列表被 `limit` 截断（解析条数 ≥ 上限），**不做缺失标记**，避免把"没抓全"当成"撤下"。
4. **多源合并**：同一活动被两个来源收录 → `cross_sources` 合并、置信度 +0.08；多源活动不参与单源缺失标记。
5. **复核**：界面上的「复核来源」会重新抓原链接并比对标题，结果写入 `verified`。

### 界面标签

- 红色「可能撤下」：连续未出现；
- 红色「已取消」：来源明确取消（默认不显示）；
- 绿色「多源收录」：≥2 个来源收录；
- 「已复核」/「待复核」：人工复核状态。

## 5. 怎么新增一所学校

1. 复制一个同 `mode` 的文件改名，例如 `uestc.mjs`；
2. 填 `id/name/school/city/category/listUrl/mode`；
3. 写 `parseList(html|json, source)`（浏览器模式暂不需要）；
4. 在 `tests/sources.test.mjs` 的注册表断言会自动覆盖；
5. 跑 `node src/recruit/cli.mjs collect --source <id> --limit 5` 验证。

不改 `collect.mjs`、`api.mjs`、前端。

## 6. 失败时怎么办（作业 1.3.1）

```
静态解析失败 → 找隐藏 JSON 接口 → 浏览器模式 → 人工转发链接
```

每个源的 `note` / `fallback` 字段写明备用通道。例如中央财经：

> 本次测试连接超时（可能是站点侧 IP 限制或网络策略），需要备用通道。
> 备用：官方微信公众号 + 人工转发链接解析。
